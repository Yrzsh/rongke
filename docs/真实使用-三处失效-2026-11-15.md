# 真实使用跑出来的三个缺陷 — 2026-11-15

> 触发方式：不信判据，起真服务（`python -m rongke --web`），用真模型
> （`commandcode / deepseek-v4.1-flash`）走真 HTTP，像用户那样提问。
> 三处失效**全部**是 7482 项回归判据没抓到的 —— 因为它们都不在「函数返回什么」
> 里，而在「模型看到什么、用户拿到什么」。

## 缺陷 1：模型把提示词里的格式样例当成导师原话

**现场**：用户说「我导师张老师说我这次组会讲得太虚……把他判断我的那一套记下来」，
工作区里没有任何材料。模型调 `advisor_save` 存下：

```
# 追问习惯
- 先问对照组。source=user
```
`meta.json`：`sufficiency: 35`，四层只有 `persona` 一层。

**「先问对照组」从哪来**：来自 `ADVISOR_METHOD_TEXT` 里那一行
「`persona`（PERSONA.md）—— 怎么问：他会先问哪几类问题 / 在哪一步不耐烦」——
**那是格式示例，不是导师说过的话**。模型把它抄下来，标成 `source=user`。

**为什么危险**：`source=` 机制的全部价值是「他真说过」与「内核替他编的」能分开。
标错之后这条再也分不开，而用户会拿这一层去准备答辩。用户后来在组会预演里拿到的
「张老师的判准」，第一条是他从没说过的话 —— 见缺陷 1b。

**修法**（`rongke/loop.py` + `rongke/advisor.py`）：
1. 提示词加第四条硬纪律：**「这段提示词里的任何例子都不是材料」**，
   并点名示例来自哪里、把示例当 `source=user` 等于替他编话。
2. 给一个**合法空状态** `NO_MATERIAL = "未挖到材料"`：一层里只写这一行
   `check_layer` 判通过。根因是「空着」原来也会被判不通过，模型没有诚实的出路
   —— 逼着它编的正是我们自己。
3. `ADVISOR_SAVE_SCHEMA` 的 `layers.description` 第一句写死这条
   （模型看 schema 比看正文多）。

**修后实测**（同一句话、同一模型）：模型列工作区 → 派子代理通读 → 判定没有材料
→ **拒绝填满**，落了一份每节都写「未挖到材料」的空档，并在回包里写明
「先把结构定死，材料到位即刻可填」。这是要的行为。

## 缺陷 2：「组会」当名词用 ⇒ 被判成「我要上讲台」

**现场**：用户说「帮我把导师的批注和**组会记录**存成一个档案」——
一个整理资料的任务，拿到的是：讲台立场段（`FINAL_VERDICT` / `[Q1]` / 镜头），
回包被按 `P0`/`R1-R12` 的评审格式盘了一遍，最后附上
「**导师视角读回：这一份现在还交不出去**……0 条带位置的问题……请补齐 R1、R6、R7、R9」。

**根因**：`_RE_REHEARSAL` 里有一个**裸的 `组会`**。`is_rehearsal_text`
命中即成立，于是「组会记录」「组会讨论」「上次组会说的」全部命中。

**修法**（`rongke/mentor_review.py`）：不是删掉「组会」，是**降宽**
（同 `_DECK_WORDS` 那条纪律）—— 要求它与「要讲 / 轮到 / 发言 / 预演 / 被问 /
今天明天下周」之一同时出现；另给「今天组会」「明晚组会」这种时间前置写法开了口子。
删掉 `组会` 会让「下周轮到组会，帮我看看」漏判，同样错。

修后 9 条判据（4 正控 + 4 负控 + 原有用例）全对，已进 `mentor_rehearsal_test.py` §④b。

## 缺陷 3（顺带）：`read_file` 的截断让模型读不完自己的会话记录

**现场**：模型想看用户在上文说过的话，去读工作区的 `conversation.json`。
`read_file` 把输出硬截在 ~12000 字符且**没有 offset 参数**，而
`result_dropped` 字段报的是「被预算丢掉多少」，不是「文件还有多少没读」。
于是模型围着这一个文件试了 `max_chars=30000`、`70000`、派子代理、导 docx 转回，
最后在回包里如实写「可见范围内零出现，其余部分未能覆盖到末尾 ——
所以准确说法是『没有找到』」。

**这条没修**（改 `read_file` 的语义面影响面太大，且本轮的失效不靠它兜底），
但它是一个真缺口：模型对「我的输入还剩多少没看到」没有可靠手段。
记在这里，下次谁碰 `read_file` 的预算逻辑时先看这条。

## 方法论（这才是本轮真正值得留的部分）

7482 项判据全绿，真人用三句话就抓出三个 P0。原因是判据全部钉在
**「给定输入，函数返回什么」**，而这三处失效发生在
**「模型看到什么」** 和 **「用户拿到什么」** 之间 —— 那一段没有判据能覆盖，
只有真跑。

所以：**判据证明「我没改坏已知的行为」，证明不了「这事对人有用」。**
两者都要做，顺序是先真跑、再补判据 —— 反过来会花一整天把错误的假设测到全绿。
（本轮确实先补了 153 项判据，然后真跑抓出 3 个它们一个都没覆盖的缺陷。）
