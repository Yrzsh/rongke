## 2. 我不同意的地方

### 2.1 「把证据门升级为『结论-证据对应』的语义核验」—— 这条会撞上项目自己的第一定律

项目第一定律是：**硬门只留可核对的验收标准**。
它的来历是本仓库最贵的一课 —— 拿"交付物措辞"当硬门，导致一次**完全正确**的交付
（119 字、偏差 −1%、体检 100/100）被连续打回，白烧一轮 113s 的 `build_references`。

而"模型判断结论是否被证据支持"**恰恰是不可核对的判据**。把它做成硬门 =
把同一节课再上一遍，只是这次误伤的判据从"措辞"换成"蕴含判断"。
代价还是那个代价：**误报会教模型学会无视整份体检报告。**

**可执行的切法**：把这条建议拆成两半 ——

- **可机器核对的子集 ⇒ 上硬门**（见 §4 第 2 件：数字锚点 / 引文锚点 / 否定锚点）。
  这三条的共同点是**判据是字符串级的事实**，不是语义判断，因此零误报风险。
- **语义蕴含 ⇒ 只做软警告 + 抽样人工复核**。它进 `warnings`，不进 `reasons`。
  理由与写作门"体检最多打回一次"完全同构：**启发式判据不许有无限打回权。**

### 2.2 「三件事并列」—— 其实是「一件仪器 + 两件被测对象」，而且前面还有一件更便宜的前置

- 第 1 件（评测集）是**仪器**；第 2、3 件是**被测对象**。
  仪器不先立起来，后两件的进展**无从判断**——这跟"只有负控的自检等于没测"是同一个道理。
- 但在仪器之前还有一件 **0 号动作**，成本以小时计，收益直接决定仪器跑不跑得起：
  **填 `pricing.models` + 打开前缀缓存。**
  算一下：33 任务 × 3 次 = 99 场；按已实测的两个端点外推（短任务 53,584 输入 tok、
  未收敛长任务 159,895 tok）⇒ 一轮评测 **5.3M–15.8M 输入 token**。
  而现在 **成本一律 `UNKNOWN`，`cache_read` 连续 9 场为 0**。
  那段固定工具 schema（15,562 字符 ≈ 6.3k tokens，占首步输入 **82.9%**）是教科书级的缓存对象。
  **不先做这一步，"建评测集"会在第一轮就被账单卡住，而且卡得不明不白（因为算不出花了多少）。**

### 2.3 「这三件做完之前，加功能都是在沙地上盖楼」—— 同意一半

HTTP MCP、桌面打包、审批钩子确实都是沙上盖楼。但**前缀缓存不是**：
它不增加任何能力，只减少成本，而它恰好是评测集的前提。它和第 0 件是同一件事。

### 2.4 战略层异议：这个对标系可能选错了

评审拿 Elicit / FutureHouse / Google co-scientist 比"做研究的能力"。
但荣珂现在真正稀缺、且**别人没有**的东西不是"更会做研究"，是
**"交付物可被审计"**（证据可追溯 + 门禁可复核 + 判定词汇不归并 + 误报成本意识）。

买门禁的人不是研究者 —— 研究者要的是结果，门禁对他只是阻力。
愿意为门禁付钱的是**机构 / 期刊 / 合规方**：他们要的是"这份稿子的每个结论都能追到一次真实调用"。

若这个定位成立，那么"不可分发"和"审计导出全缺"就不是产品化欠账，
而是**核心资产的封装度** —— 优先级要往前提，而不是排在"跨学科、多源授权"之后。
反之，如果卖点确实是"比 Elicit 更会检索与综合"，**那 6–12 个月反而乐观**，
因为那要拼数据源采购与算力，不是拼工程纪律 —— 而那两样恰恰不是这个项目的强项。

**这个岔路口比三件事里任何一件都更该先答。** 定位未答，工程补齐的每一分都在赌。

## 3. 核验中新发现的问题

### 3.0 ★ "缓存完全没生效"是**错的** —— 探针瞎了（本节最重要）

优化靶里写着「`cache_read` 连续 9 场归档恒为 0 ⇒ 前缀缓存完全没生效」。
但 `0` 只是**读数**。读数恒为 0 只有两种解释，治法完全相反：

- **(A)** 网关真没开前缀缓存 ⇒ 只能等 / 换网关；
- **(B)** 网关给了命中数，但**内核没读那个字段名** ⇒ 缓存一直在生效，是我们瞎了。

共同点是"`cache_read = 0`"，所以判别信号必须比共同点更细 —— 只能是**原始响应体里的字段名**。
写 `cache_probe.py` 同前缀连发两次，拿到原始 body：

| | 第 1 次（冷） | 第 2 次（同前缀） |
|---|---|---|
| `prompt_tokens` | 5342 | 5342 |
| `prompt_tokens_details.cached_tokens` | 0 | **5120** |
| 内核 `_usage_from` 读出 `cache_read` | 0 | **0** |

**命中率 95.8%，而内核读成 0。** 根因是一行代码：

```python
cache_read=int(u.get("cache_read_input_tokens") or 0),   # ← 只有 Anthropic 的口径
```

本项目跑在 **OpenAI 兼容网关 + DeepSeek 模型**上，命中数落在
`prompt_tokens_details.cached_tokens`。原实现只认 Anthropic 的字段名 ⇒ 恒为 0。

**这是 N 型缺陷（假阴性守门）的第二种长相**：已有的 N 型是"守卫的探针有 bug ⇒ 能力静默失效"，
这一型是"**测量的探针有 bug ⇒ 能力被读成不存在**"。后果更隐蔽：
它会**生成一个看起来像事实的结论**（"缓存没生效"），并据此排出一项根本不该做的优化。

**已修**（`rongke/llm.py::_cache_read_from`，4 家口径全认；取值规则是**认得的字段取最大值**，
不是"第一个命中的" —— 因为该网关实测**同时**在发 Anthropic 侧的 0 值残桩
`cache_creation_input_tokens: 0`，一旦它哪天补一个 `cache_read_input_tokens: 0`，
"先用先得"就会把 5120 静默覆盖回 0，**原病复发**）。
`telemetry_test.py` 新增第 13 节（12 项断言 + 1 组承重自检）钉住它，用的是**实测抓到的真实原始体**。

> **一个不能靠修代码解决的后果**：那 9 场历史归档里的 `usage.cache_read = 0`
> 是**被坏探针写下的"当时值"**。归档里的"当时值"是证据，不能重算 ——
> 所以**历史归档永久带毒**，token/成本基线只能**修完之后重新测**。
> （input_token 的量是准的，只有 `cache_read` 这一项坏；所以"一轮评测 5.3M–15.8M 输入 token"
> 这个**体量**估计不受影响，受影响的是**钱**。）

### 3.0b 顺带发现：`telemetry_test.py` 一直是红的（2 项确定性失败）

按纪律回跑全套时发现 `telemetry_test.py` 退出码 1，§4 与 §5 各挂一条负控。
用快照里的**原版测试文件**隔离 ⇒ **同样挂** ⇒ 与本次改动无关，是**预先存在**的，且**确定性**（连跑 3 次都挂）。

根因（实测）：**这台机器的 `time.time()` 步进 ≈ 1 ms** —— 连调 2000 次，
**2000 次全部与上一次精确相等**。而那两个夹具是 `start_run()` → 几条语句 → `finish()`（微秒级）
⇒ `end == start` **精确相等** ⇒ 零耗时判据（`invoke_agent` 必须 > 0）在一份**完全健康**的 trace 上报错。

判据本身没错：生产里一次 `invoke_agent` 是秒级，永远读不到 0。
错的是**"零工作量"的夹具** —— 它让负控在一格时钟都没走完的情况下断言"零问题"。
修法是让夹具真的耗掉一格时钟，并**补一条先决条件断言**（`duration_ms > 0`），
免得以后有人删掉 sleep 之后测试"又过了" —— 那时它测的是夹具，不是记录器。

> 这件事值得单独记一笔：**"72 项"被记在基线里，而它其实是"72 项里 2 项失败"。**
> 计数不是结论。**只有计数没有成败，就是 F 型假安慰换了件衣服。**

### 3.1 Q 型缺陷（新命名）：**证据不可复算**

归档 `session.json` 的 `events[kind=tool]` 长这样：

```json
{"seq": 9, "name": "record_skill_use", "args": {...}, "ok": true, "ms": 21,
 "fingerprint": "b086a189657e8518", "digest": "c3cbd63dc4fa", "ts": "..."}
```

**只有结果的摘要哈希，没有结果原文。**

后果一：证据门第 4 条依赖 `tc.result` 文本 ⇒ **任何"只审归档"的外部评测在架构上不可能复核它**。
评测必须**在线重跑**，历史归档不可复用为证据。

后果二：这**正是"审计导出全缺"的技术根因**。一份可交付给第三方（期刊/合规）的审计包，
必须能让对方**重算判定**，而不是只能相信我们打印的判定。

与已有的 **P 型（现值 vs 当时值）** 同族，但更狠：P 型至少保留了"当时值"；
Q 型连**支撑当时值的输入**都没留 —— 于是"当时值"退化成不可验证的断言。

> 最小改动（顺带服务第 2 件）：归档时为每条 evidence 落一个 `anchors` 数组
> （从结果里抽出的规范化数字 / DOI / 工具名），使门禁**可离线复算**。

### 3.2 验收覆盖这条门的可量化松口（D 型家族）

`gate.py` 第 4 条实际判据是 `_covers(acc, tc.result[:2000])`：

- **`[:2000]`**：结果前 2000 字符之外的证据**等于不存在**。工具结果越长，越容易假阴性。
- **`_covers` 是双向子串**（`a in b or b in a`）：短验收标准（"完成""已核验"）
  几乎**必然**被任何长结果覆盖 —— 这是门槛被静默开大的经典形态。

### 3.2b ★ R 型（新命名）：**内核实测可以被一句话推翻** —— 比 3.2 严重得多

这一条是写 3.2 的时候顺手做实验撞出来的，**门没守住**。本轮最该看的发现是这个。

`check()` 第 4 条原本是「**措辞命中 或 内核说达标**」，而且内核是**最后一道补充**：

```python
hit = any(_covers(acc, ev.acceptance) or _covers(acc, ev.shows)
          or _covers(acc, tc.result[:2000]) for ev, tc in real)
if not hit and self._kernel_covers(acc, rep):   # ← 只在"没命中"时才问内核
    hit = True
```

两个问题叠在一起：

1. **`_kernel_covers` 只有肯定侧是终审。** 它的返回是「达标 → 给一段文字；不达标 → 给空串」——
   于是**实测不达标**和**内核判不了**长得一模一样，两者都掉回措辞匹配。
2. **`ev.acceptance` / `ev.shows` 是模型自己填的自由文本。** 把验收标准的原文抄进
   `ev.acceptance`，`_covers()` 就精确命中。

合起来一句话：**内核量出来的事实，被被审者的一句话推翻了。**

**实测复现**（旧版 `_kernel_covers`，`.backups/20260919-093417/`）：

| 稿子（内核实测） | 模型在 `evidence.acceptance` 里写 | 门的判定 |
|---|---|---|
| 一个引用标记都没有（`citations: 0`） | 不提引用 | **打回**（"无证据支撑"）← **误报** |
| **9 处引用标记（`citations: 9`）** | 复述"全文不含任何文献引用…" | **放行** ← **假阴性** |
| **147 字 vs 目标 120（+22.5%）** | 复述"字数约120字" | **放行** ← **假阴性** |

同一道门，**干净的稿子被冤枉、违规的稿子被放行**，方向还是一个：
**它没在看稿子，它在看模型怎么描述稿子。**

> **归类**：这是 **B 型（两处真相）里最凶的一种** —— 不是"有两处真相"，
> 而是**冲突时听错了那一处**。项目原来只记了"别搞出第二份判据"，
> 没记"判据有优先级、而优先级会反"。新增形状 **R 型：自证压倒实测**。
> （Q 型是第 17 个，这是第 18 个。）

**误报那半边是真实付费的。** 运行 `20260919-092658` 里，模型被打回后的思考原文：

> 「体检 100 分通过，字数 157 字 OK。**缺的是「全文不含任何文献引用」的证据** ——
> 需要一个程序化核验工具来证明无引用。可用 originality……」

随后它跑了 `originality` / `ledger_query`×2 / `mechanical_fix`：**10 步 / 126,850 输入 token，
对比 `20260919-092312` 的 6 步 / 68,974 —— 多烧 57,876。**
（n=1，且两次路径本就不同，所以这个差值**不能**当成干净的因果估计；
但"打回理由把模型引去找证据"这件事，有它自己的思考原文为证。）

**修法（已落地，`writing_gate_test.py` 88 项全绿）**：

- `_kernel_covers` → **`_kernel_verdict`，返回三态** `pass` / `fail` / `unknown`；
  **`fail` 是终审**，直接 `continue`，不再进措辞匹配。
  规矩一句话：**内核量得出来的，内核说了算；量不出来的才交回措辞。**
- **新增引注类判据**：标准谈"有没有引用"且为**全称否定式**时，由 `citations`（文中标记）
  与 `has_refs`（文末文献表）直接判。这两件事**必须分开核** ——
  `citations == 0` 证不出"没有文献表"（只有文末文献表、正文零标记的稿子，citations 也是 0），
  拿它冒充就是 L 型超范围断言。
- **打回理由拆成两句**：实测不达标 → "**改稿**，不是补证据"；无证据 → "补证据"。
  原来混成一句，正是这句话把模型支去找证据的。
- 检测器**刻意保守**：谈引用的*质量 / 格式 / 页码 / 条数*一律判 `unknown`，交回措辞 ——
  否则「全文不得引用未经核实的文献」会被判成"不许有引用"，把合规稿硬门打回（误报比漏报更伤）。

**判别力验证**（拿新版测试回跑旧版内核，适配器如实把旧 API 的空串映射成 `unknown`）：
**旧版 6 项里 5 项失败，新版 6/6 通过。** 其中 `B1` 在旧版返回 `passed=True` ——
**上面那张表的假阴性是复现出来的，不是我推的。**

## 3.4 ★ 评测效度缺口：**评分标准（acceptance）不是固定的**

这一条是做完 §3.2b 之后顺手查的，专治"R 型还有没有别处长这样"。结论：
**其余三个门都没事**（图面门读的是审计工具返回的 JSON、引注联动读的是内核 `citations`、
技能门读的是台账里真实发生过的调用 —— 都是独立锚点）。**但契约层有一个。**

**机制**：验收标准是**起草模型自己写的**（`contract.DRAFT_SYSTEM`，只有提示词级的
"acceptance 要具体到可检验"，**没有任何强制**）。同一个目标重跑，起草结果每次都不一样。

**实测（12 场归档 / 3 个任务组）**：

| 任务组 | 场次 | 用了几套不同标准 |
|---|---|---|
| `0c1a48c3` 低温诱导摘要 | 3 | **3 套** |
| `72d32759` 冬虫夏草引言 | 7 | **6 套** |
| `cf074742` Origin 散点图 | 2 | **2 套** |

7 场那一组里，有一场只写了 **2 条**标准，而目标明说「论文**引言**草稿」——
**那一套标准里根本没有"体裁"这一项**。同一批运行里，另一场把"体裁"写成了独立一条。

**为什么这对评审第 1 条是要害**：`baseline.py` 的分母已经正确地用了「不同任务数」，
但**分子仍然不可比** —— 同一任务组的每次重复，**是被不同的尺子打的分**。
一个混了 6 把尺子的"任务成功率"，挂在汇报里照样会被读成"同一标准下的能力指标"。
**这不是拒绝出数的理由**（措辞天然会飘，硬卡字符串必误伤 —— 与本项目第一定律一致），
**但必须写在数字旁边**。

**已做（`eval/baseline.py`）**：新增 `rubric_drift()` —— 判据 = 规范化并排序后
**整套标准**去重计数 > 1。检出后写在**成功率正下方**（它是限定语，不是附注），
并如实给出**"可比组数"**：0 个可比组时印的是"**没比过**"，不是"比过了、很稳"（防 F 型假安慰）。
配了 1 正控 + 3 负控 + 1 承重自检（负控含"仅条目**顺序**不同不算漂移"、
"取不到契约判**判不了** 0/0"）。真实归档上的输出：

```
⚠ 评分标准漂移：**3 个任务组**的重复运行用了不同的验收标准（可比组 3 个）
  - …3 场里用了 **3 套**不同标准（0c1a48c3）
  - …7 场里用了 **6 套**不同标准（72d32759）
  - …2 场里用了 **2 套**不同标准（cf074742）
```

**未做（这是本条的真正修法，需要内核支持）**：让**同一任务的每次重复用同一套标准判** ——
把 `acceptance` 钉进 `eval/tasks.jsonl`，并给内核加一个"注入固定契约"的入口
（现在契约只能由模型现场起草）。**在钉住之前，任何任务级成功率都要带着这行限定语来读。**
我**没有**先往 `tasks.jsonl` 加一个用不上的 `acceptance` 字段 —— 半成品机制比没有更糟。

  而归档有 9 场带用量。**新跑的场次已正常写入台账**（`20260919-092312` 那条带
  `cache_read=61824`），所以差额是纯历史遗留、会自然愈合。
  但**给人看的那一行数字是半份真相** —— 这属于 B 型（两处真相）在**呈现层**的残留。
  建议改法：让这一行**声明自己的口径**（"台账口径，仅含 X 场"），或直接改从归档汇总。
  **没有替你做决定**，因为它同时是"台账"与"归档"两个语义不同的东西，选哪个是产品判断。
- **没建归档字段口径表**（§3.3(c) 的根因）。今天同一个坑踩了四次，说明靠人记不管用。
  该有一份集中的"归档/台账字段口径"清单（`kind` 不是 `type`、`input_tokens` 不是
  `prompt_tokens`、台账用量在顶层、`gen_ai.usage.*` 命名空间……），
  并让读归档的脚本**先自检容器**再取值。
