# 荣珂 · 产品说明

> 面向使用者与采购方的说明。开发细节、判定逻辑、接口契约在
> [`README.md`](../README.md) 与 [`docs/`](.) 里，这里只讲**它是什么、
> 能做什么、多少钱、边界在哪**。

---

## 一、它解决什么问题

科研工作里有一类活，程序能做完但人不敢交给程序，交给程序又常常
"跑通了但结果是错的"：

- 拿到一份数据表，该画什么图？—— 凭手感选，两组连续变量画折线、
  时间序列画箱线，**脚本退出码是 0，图是错的**。
- 写完一段结论，引用的文献真存在吗？—— 编出来的 DOI 和真 DOI
  长得一模一样，肉眼分辨不了。
- 做一份组会 PPT，30 页讲稿里有没有自相矛盾的地方？—— 通读一遍
  要两小时，读第二遍还是会漏。

荣珂的做法不是"再套一个提示词"，而是**在产出后面加一道判定**：
图要过六道图面门，引文要核 DOI 与撤稿状态，PPT 要体检版面与备注。
判定不过，任务就不算完成。

所以它的定位是：**一个带判据的科研 agent**，而不是一个更会说话的
聊天框。

## 二、能做什么

内置 67 个工具，33 个域（`--tools` 表头的口径：67 = 实体工具数，
33 = 已挂上的域插件数）。按你实际会做的事分：

| 你会做的事 | 荣珂给的 |
|---|---|
| 查文献 | 多源检索（Crossref / OpenAlex / Europe PMC 等）、DOI 核验、撤稿检查、引文元数据比对 |
| 读文献 | PDF 入库转 Markdown、全文抽取、按页定位原页（看的是 PDF 原页，不是抽坏的纯文本） |
| 画图 | **数据分析成图**：测列形状 → 选图型 → 出脚本 → 跑图 → 六道图面门 |
| 做 PPT | 写讲稿备注、组会 PPT 体检（页数/备注覆盖/字号/长度）、品牌模板套用、逐页渲成 PNG |
| 写课题 | 课题活文档（计划/读过什么/证据表），跨会话续上 |
| 沉淀 | 记忆与经验层、插件系统（自己加工具/图型/图注模板） |

> 数字口径：**15 种图型**是内置的；装一个插件就多一种（示例插件
> `term_bar` 可以把术语频次画成横向条形）。
>
> 15 种 = 原有 9 种（时间序列 / 折线 / 散点 / 箱线 / 小提琴 / 柱状 /
> 热图 / 直方图 / 配对）+ 2026-10 新增 6 种（区间带 / 误差棒 /
> 横向柱 / 堆叠面积 / 森林图 / 矩形热图）。新增的这 6 种是为了补上
> 「原 9 种里根本没有对应画法」的论据类型 —— 不确定性区间、组间误差、
> 长标签、构成随序变化、效应量+置信区间、长表透视。

### 数据分析成图：这是最值得单说的一块

给一张 CSV/Excel，产出的不止一张图：

1. **先量列的形状**（连续/分类/时间、缺失率、基数），再据此选图型；
2. 把「**为什么选它、为什么不选那几个**」写成理由，而不是静默决定；
3. 生成**独立可读的 `plot.py`** —— 你可以拿去改、拿去投稿说明；
4. 一次出 PDF / SVG / PNG(600dpi) / TIFF 四种格式；
5. 附一份**五点契约**（图号/标题/分面/统计口径/源数据）与**图注草稿**；
6. 过六道门：源数据可追、字形齐全、标签不撞、字体不缺字、
   文字不出框、多分面对齐。

第 6 条是关键。前五条很多工具都能做，第 6 条决定了"能不能直接送审"。

## 三、价格

四档，都按**成本价转售模型额度**，不做超额溢价。

| 套餐 | 月费 | 额度 | 席位 | 适合 |
|---|---|---|---|---|
| 免费 | ¥0 | $2 试用额度 | 1 | 试完主要功能再决定 |
| 专业版 | $29 | $30 | 1 | 单人研究者 |
| 实验室版 | $99 | $120 | 5 | 一个课题组共用课题库与模板 |
| 机构版 | 面议 | 不限 | 不限 | 私有部署 + 自建模型网关 |

**额度是什么**：模型调用成本的天花板。账单按每次任务的实际 token
成本扣减，不是按次数。

**两件必须说清的事**：

1. **当前版本没有接支付网关。** `--billing topup` 只往本地台账写一条
   记录，**不会真的收款**。这一点写在命令行输出里、写在
   `billing.py` 的模块说明里、也写在这张表下面。等接上支付才会变成
   真的入账 —— 在那之前，请不要按"已经能付款"来理解它。
2. **价格表默认是空的。** 荣珂的默认网关是第三方转售，其单价不该由
   内核猜。价格表空着时，所有成本显示为 `UNKNOWN` —— 这是
   **"我不知道"，不是"这次不要钱"**。把前者渲染成后者会让人据此
   做决策，所以宁可不给数。

### 要接真支付，该接在哪

这版刻意只留接缝。三条接缝各自的位置与职责：

| 接缝 | 在哪 | 接过去之后要保证什么 |
|---|---|---|
| 入账 | `billing.Billing.top_up()` | 只由**支付回调**调用，不由界面调用。金额取回调里的实际到账，不取前端传来的数 |
| 套餐变更 | `billing.Billing.change_plan()` | 付款成功后才调；失败不许先给额度（先给额度等于白送） |
| 幂等 | 台账里的 `run_id` 字段 | 支付方会重投回调。同一笔交易只许入账一次，用交易号当 `run_id` 去重 |

**不要**在 `/api/billing` 上加写端点。那是个只读 GET，界面拿到它就有
"自己给自己改账"的能力，而这里没有任何东西能证明付款真的发生过。
真接支付时的形态是：支付方回调 → 服务端验签 → 验签通过才 `top_up()`。

还有一件不是代码能解决的：**收款要资质**（支付通道、发票、退款条款），
那属于经营主体，不是软件功能。

### 授权：离线激活码（不需要服务器）

**先说清它管什么、不管什么。** 激活码管的是**这个软件本身的授权**，
与模型 API 的开销无关。你自己填 API key，token 的钱直接付给模型厂商，
不经过荣珂。所以：

- 激活码里**没有** token 额度。有的话就等于我们替厂商收钱。
- 你换更大的 key、跑得更狠，与授权状态无关。
- 上面那张「余额」表是**你自己的成本估算**，不是收款凭据。

**30 天试用**，从首次启动控制台算起。到期后**只拦"发起新任务"与会话内追问** ——
历史、产出、文献库照常能看。被锁在自己文件外面既帮不上"提醒你该买"，
又让人愤怒，所以刻意不做那种形态。

| 你要做什么 | 命令 |
|---|---|
| 看现在什么状态 | `rongke --license` |
| 取本机机器码 | `rongke --license machine-id` |
| 粘贴激活码 | `rongke --license activate RK1.xxxx.yyyy` |
| 换机器 / 注销 | `rongke --license deactivate` |

界面上对应侧栏「授权」那一页，粘贴即可，不必敲命令。
**Windows 安装版没有 `rongke` 命令，激活请用这一页**；源码 / wheel 用户两种方式都可以。

**一码一机。** 授权页显示本机机器码（形如 `RK-M-XXXXXXXXXXXXXX`）。
客户把它发给你，你用私钥签进激活码的 `mid`；码只在这台机器有效。
重装荣珂（同一台机器）仍可用；换机或重装系统后机器码会变，需要新码。
没有服务器、不联网，机器码本身是 `MachineGuid` 的哈希，不包含用户名等个人信息。

**它为什么不需要服务器。** 激活码是用 Ed25519 **私钥签出**的一段凭证
（客户名、套餐、到期日），程序里内嵌对应的**公钥**做校验。全程离线：
不联网、不上报、不发任何数据出去。私钥只在发行方手里。

**能防什么、不能防什么。** 能防：改到期日、改套餐、伪造凭证、拿别人的
凭证换个名字用 —— 改一个字就验不过；也能防把同一行码直接发给另一台机器
（`mid` 与机器码不一致就拒绝）。**不能防**懂 Python 的人删掉校验那一行，
或者伪造 `MachineGuid`。这是解释型语言的固有边界，所有不加密狗的商业软件
都一样。所以它的作用是**让诚实的人走正道**，不是拦住铁了心要破解的人。

**发行方**（你自己）用的两条命令，买家不用：

```bash
rongke --license keygen                          # 只跑一次，生成一对密钥
# 把输出的公钥填进 rongke/license.py 的 EMBEDDED_PUBKEY，
# 私钥记在别处 —— 它**绝不能进仓库**（packaging_test.py 会拦）

rongke --license sign --sk=<私钥> --mid=RK-M-XXXXXXXXXXXXXX \
  --customer "某大学" --lic-plan pro --days 365
# 输出一行激活码，发给买家；--mid 是客户授权页显示的本机机器码
```

**私钥要用等号形式（`--sk=…`）传。** base64url 的私钥可能以 `-` 开头，
写成 `--sk <私钥>` 时命令行解析器会把那个值当成另一个选项，报
`expected one argument`。这个坑只在私钥恰好以 `-` 开头时出现，
所以时好时坏 —— 别去猜，一律用等号。

`--days 0` 表示永久授权。私钥泄露等于任何人都能签出有效码，
所以它和信用卡是一个级别的东西。

### 订阅与授权口径（v2，2026-11-06）

**上面这张四档表是「成本预算的占位」，不是订阅价。** 表里的 `price_usd` /
`quota_usd` 是本地账单估算 token 花费用的占位值，代码里已注明不是定价决策；
荣珂默认 **BYOK**（自己填模型 API key），token 的钱直接付给模型厂商，
不经过荣珂。软件本身的授权是另一条线：30 天试用 → 离线激活码，见本节上文。

v2 把收费对象收敛为**期限授权**：个人年费、买断、课题组、机构、赠送档。
凭证里带档位、起算点、期限、订单号与渠道，**不带任何 token 额度**。
新码始终带 `expires`（由 `starts_at + duration_days` 推算），所以 0.1.8 的
内核一行不改就能验；`plan` 直接写中文可读档位，授权页不必改前端。
发行侧形状单源是 `tools/issuing_lib.py`，配套
`tools/issue_code.py` / `tools/order_new.py` / `tools/reconcile.py`。

控制台「首次配置」页显示的「免费 / 专业版」等名称来自**本地成本预算档**
（`billing.py` 的 `PLANS`），**不是你购买的订阅档位**；订阅档位在
「试用与激活」页读激活码。两处名称不同是已知的展示层缺口，留到 0.1.9 分栏。

⚠️ **仍然没有接支付网关**：订单工具只写本地台账，`--confirm-payment`
必须由验过签的支付回调调用，不由界面调用；自动续费、即时撤销、中途退款
在离线激活码架构下做不到，不承诺。完整方案与验收判据见
[订阅与授权方案 v2](订阅与授权方案-v2-2026-11-06.md)。

## 四、边界（这一节请务必读）

诚实说明做不到的事，比列出能做的事更重要。

### 它不是多用户系统

荣珂是**单机工具**。`--billing password` 设的密码只用于
"防止别人路过你的电脑顺手打开控制台"，**不是**用来防有磁盘权限的
攻击者 —— 能读你数据目录的人本来就能改台账。

设了密码之后，控制台会拦下除首页与 `/api/auth` 之外的所有接口；
会话令牌只存在控制台进程的内存里，进程一停就要重新登录。
**没设密码时不会拦任何东西** —— 这是单机工具的默认，不是漏洞。

真要让多人共用一台机器，得靠操作系统的用户隔离。

### 它不保证引文正确，只保证"能查出错的"

引文核验能发现：DOI 不存在、DOI 指向另一篇文献、论文已被撤稿、
元数据对不上。它**不能**保证一篇真实存在但结论不成立的文献
被正确引用 —— 那需要读全文，是另一件事。

### 图面门只管"这张图合不合规"，不管"这张图对不对"

六道门核的是字形、碰撞、字体内嵌、文字出框、分面对齐、源数据可追。
它们**不判断**你选的统计方法是否恰当。方法和结论仍然是作者的责任。

### 它跑在你自己的机器上

没有云端账号，数据留在本地数据目录。代价是：换机器要自己搬数据，
也没法在浏览器之外协作。

### 定价数字是占位

`$29` / `$99` / `$2` 这些数字没有经过成本结构测算、竞品分析或
支付意愿调研。它们写在 `billing.py` 的 `PLANS` 表里，改一个数就能换。
用占位而不是编一组看起来专业的数字，是为了不让它们被误当成
经过测算的结论。

## 五、开始用

```bash
# 1. 装
pip install -e ".[figure]"        # 画图要 matplotlib/pandas 那组
rongke --version                  # 确认装上了什么

# 2. 配模型通道（密钥走环境变量，不写进配置文件）
setx RONGKE_API_KEY "你的key"

# 3. 自检 —— 会告诉你现在能干什么、还差什么、下一步敲哪条
rongke --setup

# 4. 打开控制台
rongke --web
```

装了 `[figure]` 那组之后，控制台会多出「数据分析成图」：选一张数据表，
它会看图型给建议并说明理由，画完再把六道审计门的结论逐条摊给你抄。

控制台默认**不需要登录**（单机工具）。想给它加一道门就设个本地密码
——**这只能防"路过的人顺手打开"，不防有磁盘权限的人**：

```bash
rongke --billing password 你的密码     # 设完之后打开控制台要输它
rongke --billing password ""           # 取消密码，回到免登录
```

或者直接跑一个任务：

```bash
rongke "把 data.csv 画成发表级的图，出 PDF 和 SVG"
```

### 常用命令

```bash
rongke --setup            首次自检 + 下一步引导
rongke --tools            看全部 67 个工具
rongke --billing          看余额、套餐、用量
rongke --pricing          填价格表（不填则成本显示 UNKNOWN）
rongke --plugins          看插件台账（含加载失败的及原因）
rongke --figure           图面体检装置能不能用
rongke --mcp-doctor       MCP 协议层能不能开工
```

这些数字在**控制台**里也都能看：`rongke --web` 打开后，「首次配置」页
下半张卡是「用量与额度」（余额 / 套餐 / 台账位置 / 坏行数，以及
「本版没有接支付网关」这句话本身）；「科研工具」「它能做什么」两页
分别对应 `--tools` 与 `--setup`。

## 七、已知的坑

这些是我们自己踩过、并且已经写进测试的：

- **matplotlib 3.11** 把 `boxplot(labels=)` 改名成 `tick_labels=`，
  旧写法直接 `TypeError`。
- 把列强转成字符串会**删光**数值行 —— 热力图会变成一张全白的图，
  而六道门全是绿的（门看不见空白图）。
- 配对图有 NaN 时不做清洗会静默丢点。
- 图注里的统计检验方法**不能由程序代填** —— 荣珂会留一个 `___`
  占位，因为你必须自己填实际用的检验。

每一条都有对应的回归用例，不是"应该不会出问题"。
