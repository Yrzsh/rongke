## 2. 是否仍按「最开始设置的工作流」运行

### 2.1 链路形状：一致

三场事件流都是同一条链，没有跳过任何环节：

```
contract_drafting → contract(5–6 条可验收条款) → memory_recall → tools_mounted
  → load_skill(3–4 次) → kb_search → kb_read → kb_bibtex → verify_citation
  → write_file → deliver_attempt(门) → 补正 → deliver_attempt(pass) → final + 落盘
```

口语约束仍被 100% 起草成条款：「别替我编结论」「文献用库里的」「别编 DOI」「别套话」都在
`contract.acceptance` 里；三场都**没有**反问卡住（`ask/intervene = 0`），直接按保守口径写。

### 2.2 九门：1–7 在场，8/9 本任务不适用

| 门 | A | E2 | D2 |
|---|---|---|---|
| ①–⑤ 证据门（真实 `call_seq` / 每条验收被覆盖 / 交付物被提及） | 拦 1 次 | 直接放 | **拦 1 次**，理由都是「文中不出现『已确认融合子』这类断言」那条没证据 |
| ⑥ 技能门 | 4 次 `load_skill` | 3 次 | 4 次（含 `nature-ref-verifier` / `nature-writing` / `nature-polishing`） |
| ⑦ 稿面门 | 96 分 | 92 分 | 100 分，量出 34 个指标 |
| ⑧ 图面门 / ⑨ PPT 门 | 不适用（本任务无图、无 deck） | 同 | 同 |

⚠️ **`paper-writing` 的 14 项门禁指标「配置在场」有实证**（`preset_mounted.values.gate.measured_metrics`
长度 14），但**这轮真跑里没有出现任何一条新指标把稿子打红** —— 稿子本来就干净。
「14 项判据真的会拦」的证据来自单元正负控 `_realp/preset_evidence.py` **27/27**，
不是端到端。**不能把「尺子挂上了」说成「尺子这轮量出问题了」。**

### 2.3 变的是什么：不是工作流，是尺子

这正用户要的形态 —— 同一个工作流，只换挂载的插件：

| 卡点 | A（旧行为） | D2（挂 `paper-writing`） |
|---|---|---|
| Q4 〔n〕引注失明 | `cite_numbers=0` | `citations=10`、`cite_first_order=[1..8]` |
| Q3 字数量纲漂移 | 两行数字不同源 | `unit=display_unit=chars_eq`，同一数 |
| E4 手算字数 | thinking 里「让我数一下」 | `writing_metrics` 调 5 次，自述数字首次与实测一致 |
| Q1 抄验收标准原文即放行 | 允许 | `evidence_fallback=false`（**本轮修过一次误伤，见 §4**） |
| Q5 追问新约束 | 不进验收 | `merge_new_constraints=true`（单元级已验，本轮未做端到端追问） |
| E1 工具 schema 重发 | 每步 42,753 字符 | `refresh=once`，全程 `tools_schema_chars_variants=[43069]` 一种 |

### 2.4 仍然没按最初设想跑的部分（如实）

- **两套 id** 未修：`POST /api/run` 回 uuid，产物在时间戳归档目录，`/api/follow` 只认 uuid。外部复核脚本第一次必扑空。
- **`prompt-sections.complete` 未接进 `_install_builtins`** ⇒ `stats-review` 的 `stats-checklist` 还不会真进 system prompt。
- **恒亮警告**：「交付物描述与证据措辞没有交集」在 A / E2 / D2 每次交付都亮（D2 两次、E2 一次），
  `paper-writing` 的 `stage.dedupe_warnings=false`。用户会被训练成无视警告。
- **成本不可观测**：三场 `cost_display=UNKNOWN`，`pricing.models=[]` 未修。

## 3. 产物质量：三个必须说清的真问题

### 3.1 ★ 门只量「模型粘贴的那一份稿」，不量落盘全文（Q6 未根治）

D2 落盘 `讨论_初稿.md` **1911 字符**，其中含 8 条 `[n]` 文献表；但两次交付的
`lint.metrics` 都是 `has_refs=0 / refs_n=0 / chars=921` —— 模型只把 921 字正文塞进
`draft_text`，文献表只在文件里。**门放行的 100 分，是在「只有正文的那一份稿」上拿的。**

这是最初 Q6「`_draft_text` 只认一份稿」的延伸，不是新 bug，但 `100/100` 容易读成「全文都验过了」。
独立复核 `audit_live.py D2` 也据此把引注锚点读成 0。

### 3.2 ★ 引注变「可数」的同时，变「不可溯源」（本轮新发现，方向相反）

- A / E2 用 `〔库·kbXXXX p.N〕` **带页码锚点**：`audit_live` 能算「读 / 检 / 忆」。
  E2 的 8 处锚点里 **5 处落在本次 `kb_read`，另 3 处（`kb5800c60a` p.1 / `kb4452729c` p.15 /
  `kb647981e1` p.13）既没读也没检索命中** —— 库内文件确实存在，但属 11-03 记录过的「忆档引注」。
- D2 改成 `[1]–[8]` 编号 + 文献表里 **不带页码** 的 `〔库·kbXXXX〕`。
  `ANCHOR_RE` 要求 `p.N` ⇒ 复核脚本报「引注锚点 0 处」。
  **「读不到」≠「不符合」**：不是引注没了，是**可核验性判据失明了**。

写稿过程中模型是知道页码的（thinking 里明确写着 `kb91857755 p.3`、`kb58283f09 p.2`），
最终稿把页码删掉。**预设让 `citations` 可数，却让「这条引用我到底读没读过」不可核。**
另：D2 只跑 1 次 `verify_citation`（且报作者元数据不符），随后把所有 DOI 从文献表移除；
A 是 6 次核验 / 3 条真 DOI，E2 是 9 次 / 4 条 DOI。用户原话是「别**编** DOI」，不是「不要 DOI」。

✅ 已逐一核实：D2 文献表 8 个 `doc_id` **全部在库内 `texts/*.txt` 真实存在**，没有编造文献。

### 3.3 效率：预设没有省钱

D2 26 步 / 1,417,766 输入 token，比 A（22 步 / 1,164,340）多 **22%**，
比同样现在的 E2（15 步 / 738,073）多 **92%**。缓存命中仍 ~96%，但 `cost_display=UNKNOWN`
⇒ **跑完仍算不出这轮多少钱**。E1 的 schema 缓存确实只发一份，省下的是固定前缀，
没抵掉 26 步全量历史的重发（E2 上下文峰值 101,700 字符，D2 116,554）。

## 4. 本轮实测抓到并修掉的一个**真回归**（必须先说）

修门**之前**的 D 场（同一话术 + `paper-writing`）跑了 **652.5 s / 15 步 / 3 次交付全拒 /
2 次弹窗问人 / `final=0 字`，我主动取消**；磁盘上其实已写好 `讨论.md`，`citations=14`、
`cliche_hits=0`、100 分，**就是交不出去**。

根因：`evidence[].acceptance` 按协议**本来就该填验收标准原文**（它是「这条证据绑定哪条标准」的声明），
而 P2 的 Q1 实现拿这个绑定字段判「抄原文」，再把整条证据短路掉 —— 连 `shows` 和工具回包一起否了。
7 条语义标准全被判「无证据」，门成了死门。

**修法**（`rongke/gate.py`）：Q1 改为只看**实质内容**
（`shows` / 工具 `result`）是不是复述；绑定字段不再参与判断。
`presets_live_test.py` 加端到端正负控（真调 `CompletionGate.check()`）：
「绑定字段=标准原文＋实质证据 ⇒ 不判无证据」／「shows 与回包都只抄原文 ⇒ 判无证据」／
「baseline 仍允许纯复述放行」。修后 **73 项 / 0 失败**，锚 **24 键 / 0 不一致**。
⚠️ `_realp/preset_evidence.py` 的 Q1 断言只量「开关＋`_echo_of()`」这个判据部件，
**承重的是常驻探针那三条端到端**，不能拿 27/27 当成门的证据。

修门后 D2 第一次交付只剩 **1 条**验收未覆盖（死门时是 7 条全拒），模型补一段实质证据即放行 ——
**门回到「该拦的拦、该放的放」，不是变成橡皮图章。**

另有两场非质量事件，按纪律如实归因、不计入比较：
- `E`（首次不带预设对照）：`crash` = `LLMError … Tunnel connection failed: 502 Bad Gateway`（重试 3 次），
  `steps=4` 中断 ⇒ **传输层偶发**，重跑 `E2` 正常。
- `D` 跑完后的 `/api/tools` 临时工具已自动撤销（重启后 `tools=66`、`writing_metrics=False`）。

## 6. 结论

> **工作流还是最开始那一条**，九门里与本任务相关的 1–7 门都在场、链路没跳过环节；
> 变的只是挂载的能力插件 —— 这正是「不同任务＝不同预设」想要的形态。
> **稿面质量是三场里最好的**（100 分、−5% 字数、引注可数、自述数字第一次说准）；
> 但**「更严」还没等于「更可核验」**：门只量模型粘贴的那一份稿、引注改形态后锚点复核失明、
> 成本仍黑箱、token 反而涨。**界面观感刚从「完全看不出换了预设」补到「看得见」**，
> 但胶囊藏得深、文献表不进答复、恒亮警告这三条还会直接影响用户的第一印象。

### 建议（按性价比，未实施，不擅自扩大本轮范围）

| 优先 | 动作 | 为什么 |
|---|---|---|
| P0 | 交付门量**落盘全文**（`draft_path` 与 `draft_text` 取并集，或以文件为准） | 现在的 100 分只覆盖 921 字正文，8 条文献表在判据之外 |
| P1 | 锚点复核判据兼容「不带页码」形态，或预设强制保留 `p.N` | 否则「引用读没读过」永远读不到；顺带把 3 处忆档引注纳入判据 |
| P1 | `dedupe_warnings=true` 或只在无实质证据时亮警告 | 恒亮警告会训练用户无视警告 |
| P2 | `final` 附文献表 / 补 `pricing.models` / 统一三处 id | 观感与可观测性，成本都不高 |
| P2 | `prompt-sections.complete` 接进 `_install_builtins` | 目前 `stats-checklist` 只挂载不生效，属「工具给了、判据没给全」 |
