# 插件开发

荣珂的核心是零依赖的，插件让它能长东西而不改内核。一个 `.py` 文件放进
`~/.rongke/plugins/` 就生效，不需要装包、不需要重启系统、不需要碰源码。

三类扩展点，任选其一或全用：

| 扩展点 | 方法 | 加完能干什么 |
|---|---|---|
| 工具 | `tools()` | 模型多一个可以调用的能力 |
| 图型 | `chart_kinds()` | 数据分析成图多一种画法 |
| 图注模板 | `legend_templates()` | 换个期刊的图注措辞 |

---

## 一、五分钟起步

```python
# ~/.rongke/plugins/hello.py
from rongke.plugins import Plugin
from rongke.tools import Tool

class Hello(Plugin):
    name = "hello"
    version = "0.1.0"
    description = "最小插件"

    def tools(self):
        yield Tool(
            name="shout",
            description="把一段文字变成全大写",
            parameters={
                "type": "object",
                "properties": {"text": {"type": "string"}},
                "required": ["text"],
            },
            fn=lambda text="": str(text).upper(),
            domain="core",
            mutating=False,      # 只读，不写盘
            source="plugin",
        )

PLUGIN = Hello()             # 模块级入口
```

验证：

```bash
rongke --plugins        # 看台账（成功/失败/原因）
rongke --tools          # shout 应该出现在列表里
```

## 二、三条不可让步的纪律

写插件前先读这三条，它们都是踩过的坑。

### 1. 插件不许静默失败

加载失败时荣珂**不会**悄悄跳过你，而是把它留在台账上：

```
✘ hello 加载失败：缺依赖：matplotlib
   修法：pip install "rongke[figure]"
```

`rongke --plugins` 在有失败项时**退出码是 1**，可以直接挂进脚本做前置检查。

**"装了但没生效"是最坏的状态**，因为它伪造了一个不存在的能力。
所以：插件加载了却什么都没产出（没有工具、没有图型、没有图注模板），
也会被判失败并明说。

### 2. 插件不许悄悄顶掉内置

内置工具带审计语义。一个同名插件把 `plot_data` 替掉，图面门就会去审一个空壳。

默认行为是**拒绝**，并在台账里点名是哪个工具冲突了。确实需要覆盖时，
在插件类上写 `override = True`——这是显式的，看得到。

### 3. 插件声明的依赖缺失要说人话

```python
class P(Plugin):
    requires = ("matplotlib",)      # 声明出来
```

没装时荣珂会说「插件 P 需要 matplotlib，请 `pip install "rongke[figure]"`」，
而不是把 `ModuleNotFoundError` 回溯甩给用户。

## 三、加一个图型

图型比工具麻烦一点，因为**只登记元数据是不够的**——那样
`recommend()` 会建议一个画不出来的图型。所以必须同时给 `template`。

```python
from rongke.plugins import Plugin
from rongke import analysis as A

def _applies_term_bar(cols):
    """什么时候建议这个图型。返回 None 表示这批数据不适用。"""
    if len(cols) != 2:
        return None
    lab, cnt = cols[0], cols[1]
    if not lab.is_category or not cnt.is_numeric:
        return None
    if not lab.n_total or (lab.n_unique / lab.n_total) < 0.8:
        return None
    return A.suggest(
        "term_bar", x=lab.name, y=cnt.name,
        why="标签逐行唯一 + 数值计数，这是排行表。",
        rejected=["bar：竖着放长标签会挤成一团。"])

class P(Plugin):
    name = "term-table"
    version = "0.1.0"

    def chart_kinds(self):
        return {"term_bar": {
            "family": "compare",          # 同族只留一条建议
            "name": "术语频次（横向条形）",
            "needs": "1 个文本列 + 1 个计数列",
            "template": '''
def draw(df):
    fig, ax = plt.subplots(figsize=(WIDTH_MM / 25.4, HEIGHT_MM / 25.4))
    ax.barh([str(v) for v in df.iloc[:, 0]],
            [float(v) for v in df.iloc[:, 1]])
    ax.set_xlabel({xlabel!r})
    ax.set_title({title!r})
    fig.tight_layout()
    return fig
''',
            "applies": _applies_term_bar,   # ← 不给它就只能手动指定
        }}
```

### `draw` 的契约（严格）

```python
def draw(df):        # ← 只有一个参数，返回单个 fig
    ...
    return fig
```

- **签名必须是 `draw(df)`**。写成 `draw(df, spec)` 会在运行时抛
  `TypeError: missing 1 required positional argument`，而那时图型已经
  注册成功、已经被建议、脚本也已经生成好了——错误被推迟到用户点"画"
  的那一刻。所以荣珂在**加载期**就静态校验签名并拒绝。
- **返回单个 `fig`**，不要返回 `(fig, ax)`。
- **不要自己 `savefig`**。存盘由内核的 epilogue 统一做（那里才有
  审计要的 `.pdf` / `.svg` / `.tiff` 字面量）。
- 脚本头部已预置 `plt` / `pd` / `Path` / `WIDTH_MM` / `HEIGHT_MM`，
  并设好 rcParams（字体、字号、矢量嵌入、dpi）——**不要重复设置**。

### 可用占位符（只有这 10 个）

```
{x!r} {y!r} {group!r} {title!r} {xlabel!r} {ylabel!r}
{fit!r} {table!r} {stem!r} {out_dir!r}
```

注意是 `xlabel` / `ylabel`，**不是** `x_label` / `y_label`。写成后者会被
`build_script` 的残留检查拦下：`绘图模板里有没替换的占位符：['{x_label!r}']`。

`width_mm` / `height_mm` **不是** body 的占位符（它们只在脚本头部被替换）。

### `applies` 为什么要收紧

`applies` 写成"有两个分类列就建议"会让你的图型到处冒出来，挤掉真正
贴切的内置建议。那比不扩展更糟——它污染了建议器的判断。

好的 `applies` 是窄的、有理由的、并且**会返回 `None`**。

`applies` 抛异常不会拖垮内置建议：荣珂会打一行到 stderr，跳过你的图型，
其余建议照常给出来。

### 可用的列属性

`cols` 是 `list[Column]`，每列有：

| 属性 | 含义 |
|---|---|
| `.name` | 列名 |
| `.kind` | `numeric` / `category` / `time` |
| `.is_numeric` `.is_category` `.is_time` | 同上，布尔形式 |
| `.n_total` `.n_missing` `.n_unique` | 行数 / 缺失数 / 唯一值数 |
| `.numeric_ratio` | 能解析成数值的比例（0~1） |
| `.min` `.max` `.mean` | 数值列的摘要 |
| `.sample` | 前几个值 |

## 四、换图注措辞

只对**你声明的那个期刊**生效：

```python
class P(Plugin):
    name = "my-journal"
    version = "0.1.0"

    def legend_templates(self):
        return {"myjournal": "Fig. {fig_id} | **{title}** n = {n}。"}
```

可用槽：`{fig_id} {title} {letter} {claim} {n} {center} {spread}`。

**这是措辞覆盖，不是豁免审计。** 拼出来的图注仍要过
`figure.audit_legend`（它核四段是否齐）。槽名写错时会静默退回内置草稿，
不会给用户一条空图注。

## 五、加载顺序与调试

搜索路径（按优先级，同名插件先到先得）：

1. 环境变量 `RONGKE_PLUGINS`（`;` 分隔多个目录，测试/部署用）
2. 配置文件里的 `plugins.dirs`
3. `~/.rongke/plugins` —— 你的个人插件
4. `<data_root>/plugins` —— 跟着数据走的项目内插件

`_` 开头的文件不会被当成插件（放私有辅助模块用）。

```bash
rongke --plugins-dirs    # 看搜索路径，以及每个目录里有几个候选
rongke --plugins         # 看台账（含失败原因与修法）
```

单个插件可以独立跑起来自查（示例见 `examples/plugins/term_table.py`
里的 `_demo()`）。

## 七、边界：什么不该做成插件

- **改内置工具的行为**——那是 patch，不是插件。用 `override = True`
  覆盖意味着你接手了它的全部审计责任。
- **绕开图面审计**——插件图型照样要过六道门。过不了说明图有问题，
  不是审计有问题。
- **往 `site-packages` 里塞文件**——插件只从上面那四个目录加载，
  不扫任意已安装包的顶层模块（那会把第三方库当插件去 exec，是安全问题）。
