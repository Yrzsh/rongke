# 荣珂 · 质量与效率卡点定位（基于 2026-11-04 三场真人实测）

> 本文不是"问题清单的复述"。上一份《真人论文写作请求-实测-2026-11-04》列的是**现象**；
> 这里把现象追到**代码里的那一行**，并给出可量化的影响与验收判据。
> 所有数字来自 `_realp/out/*_snapshot.json` 的全量事件流，脚本 `_realp/bottleneck.py` 可复跑。

## 0. 口径与边界

| 项 | 值 |
|---|---|
| 证据 | A / B / C 三场真实运行的完整事件流（含每次 `llm_call.messages_chars`、`llm_done.usage`、`tool` 回包、`deliver_attempt`） |
| 方法 | 只读诊断；**未改 `rongke/` 任何产品代码**，无需回跑回归 |
| 量纲 | `t` 为 `HH:MM:SS`；`wall` 由首末事件时间差算，与 API `elapsed` 独立 |
| 边界 | 各任务单次运行，**不构成成功率**；未做专家盲评，不判科学结论对错；B 的材料是合成占位夹具 |
| 固定前缀估算 | 用每场 `cache_read` 的**最小值** × 调用次数当经验下界（首步缓存段 = SYSTEM + 工具 schema）。这是下界，不是精确计费 |
| 环境 | Python 3.12.10 · `commandcode / deepseek-v4.1-flash` · 工具注册表 66（本场挂 59） |

**一句话结论**：效率的钱主要烧在"每一步都把不变的东西重发一遍 + 判据只在最后才跑"；
质量的上限卡在"内核量得出来的指标没进门，进门的判据又只认模型自己写的措辞"。

## 2. 效率卡点（按可省量级排序）

### E1　工具前缀开局算死一次，全程每步重发 —— 根因 `loop.py:4540`

```
schemas = self.registry.openai_schemas(_mount["allow"])   # 整场只在这里算一次
tools_schema_chars = len(json.dumps(schemas, ...))        # 4540–4551
```

- 实测 `tools_schema_chars = 42,753` 字符、**22 次调用变体数 = 1**（A 的 `tools_mounted` 事件
  `allow=59 / total=66 / schema_chars=42753`），累计重发 **940,566 字符**。
- A 实际只用了 8 种工具（`load_skill / kb_search / kb_bibtex / kb_read /
  verify_citation / lab_method / write_file / read_file`），B 3 种、C 4 种。
- 按 `cache_read` 下界（21,120 tok/次）估：固定前缀 ≈ **464,640 tok = A 全程 40%**、
  B **70%**、C **46%**。
- 代码注释（`loop.py:4547-4550`）已经写明"每次调用都要重发这坨 schema"，但当前只做到
  **量出来**，没做到**收回去**。按域挂载只排除 ppt 域，域内仍是全量。
- ⚠️ 缓存命中 93–96% **不等于零成本**：prefill 延迟仍在，且本场价格表不全，
  命中段究竟打了多少折无法核对。

**验收判据（修完怎么知道好了）**：同一夹具重跑，`llm_call.tools_schema_chars` 出现
≥2 种变体，且 `input_tokens` 下降能被 `schema_chars` 减少量解释。

### E2　全量历史逐步重发，压缩阈值贴着实际体量 —— 根因 `loop.py:4786`

- A：`messages_chars` 15,716 → **117,804**（7.5×），单步 input 26k → 71k tok。
  `compact_target_chars = 120000`，A 峰值 **117,804，差 2,196 字符没触发压缩 ⇒ 全程一次没压**。
- C：追问继承 A 的完整 58 条消息，**第 1 步就 117,899 字符 / 72,032 input tok**，
  第 2 步 119,785 / 73,245；直到**第 3 步之前**才压 121,356 → 56,952（省 64,404 = 53%，
  `orphan=15`）。⇒ **前两步白背 145,277 input tok**，只为改一句话。
- 压缩只看绝对字符阈值，不看"这段历史本轮还有没有用"；追问轮完全可以先脱水再发。

### E3　判据只在交付那一刻跑，返工按整场上下文计价 —— 根因 `gate.check` 仅在 `deliver_task` 调用

- A 第 1 次 `deliver_attempt` 在 `12:57:47`（第 20/22 步），此前 **20 步零验收校验**；
  打回后补 2 步、**31 s / 142,861 tok**（占全程 12.3%）。
- B 第 1 次在第 6/7 步，打回后 **22 s / 34,994 tok**（16.5%）。
- 打回理由本身是对的（A 缺"保持不确定说法"证据、B 缺缺失清单），但**作用时机太晚**：
  越晚判，返工越要把已经膨胀的历史再发一遍。

### E4　模型没有"量字数"的工具，只能手算外推 —— 工具注册表 66 个里无对应项

内核 `writing.lint()` 在 `gate.py:474` 才跑，结果只以**文字报告**回灌，模型过程中拿不到数。
实测 thinking 里出现明确的手算：

| 场次 | 原话（节选） |
|---|---|
| A 第 13 步 | `Now check word count of body (excluding references). Let me count roughly. Body is about 1400 characters?` |
| A 第 14 步 | `正文…字数估算：全文 2007 字符含参考文献。参考文献约占 ~700 字符…让我数一下正文` |
| B 第 6 步 | `The gate flagged: word count measured 322 (its counting method with English words). Need 405-495.` |
| B 第 7 步 | `470 字符时判 322 字。比值约 0.685。现在 634 字符 → 约 434 字…让我估算` |
| C 第 3 步 | `Need to check word count: 1361 chars total file including heading. Body ~1340 chars?` |

B 为了"猜中"内核口径，把正文从 470 字符扩到 634 字符（+35%）。这是典型的
**「这件事，我给了它工具吗？」** —— 没工具，写多少字数纪律都只能靠模型拿比值外推。
连带后果：`final` 自述「1100 字 7 段」实测 1037 字 8 段。

### E5　成本不可观测 —— `pricing` 表不全

三场 `charged=UNKNOWN` / `exact=false`，`unknown_charges` 递增 62→63→64。
E1–E4 省下多少 token 都无法折算成钱，**效率优化缺少闭环信号**。

## 3. 质量卡点（按"上限被谁压住"排序）

### Q1　验收覆盖靠"把标准原文抄进自述字段"即可放行 —— 根因 `gate.py:53` + `gate.py:497`

```python
def _covers(needle, hay):        # gate.py:53
    a, b = _norm(needle), _norm(hay)
    return a in b or b in a      # 双向子串
...
hit = state == KERNEL_PASS or any(
    _covers(acc, ev.acceptance) or _covers(acc, ev.shows) or _covers(acc, tc.result[:2000])
    for ev, tc in real)          # gate.py:497
```

`evidence[].acceptance` / `.shows` 是**模型自填**的。`_kernel_verdict` 只对 4 类
（字数 / 段数 / 句数 / 引注有无）给终审，其余全落到这条字面匹配。

实测 A：第 1 次门以「全文不出现融合子断言…保持不确定说法」无证据打回；第 2 次模型
把**该条标准原文**填进 `call_seq=17` 的 `evidence.acceptance`（第 1 次这里填的是第 4 条），
并把 `shows` 改成「身份判断一律用 may/suggests 级」⇒ **门放行，92→96 分**。
B 同样：补的 `shows` 是「稿件未引入记录外任何一个数值」这句自述，门不核正文。

> 模型这次确实也改了稿、数值也真的对（已独立复核），但**门的通过不依赖这一点**：
> 它依赖的是模型措辞。这正是 `gate.py:328-341` 记录过、并且只在"内核可量"那 4 类上
> 修好的漏洞 —— 语义类验收仍全部裸露在自述之下。**「自称成功」永不算证据**。

### Q2　内核量了 34 个指标，门只认 6 个 —— 根因 `gate.py:358-407`

| | 值 |
|---|---|
| `lint.metrics` 字段数 | **34** |
| `_kernel_verdict` 实际读取 | `chars` / `chars_delta_pct` / `paragraphs` / `sentences` / `citations` / `has_refs` = **6** |
| 量了但没接进门（28 个） | `cliche_hits`、`cliche_density`、`defensive_hits`、`absolutes`、`tail_repeat`、`cite_first_order`、`cite_numbers`、`placeholders`、`jargon_hits`、`chars_excl_refs`、`refs_n` … |

最刺眼的一处：**A 契约第 ⑤ 条就是「未使用无信息量的套话式段落」**，
而 `cliche_hits` 已经量出来了（本场为 0），门却走措辞匹配。
**判据的覆盖面 = 产出的上限**：量得出的东西不进判据，等于没量。

### Q3　字数判据的分子与展示用了两个量纲 —— 根因 `writing.py:373-375` 与 `gate.py:361-364`

`writing.py:573-581`：`chars_delta_pct` 用 `_eq = chars + en_words×1.6`（即 `chars_eq`）算；
但 `writing.py:373-375` 打印「当前 `m['chars']` 字，偏差 `chars_delta_pct`」，
`gate.py:362` 同样把 `m['chars']` 与按折算值算的偏差拼在一句里。

| 场次 | 报告首行「体量」 | 报告次行「当前」 | 门判的偏差 | 按显示值本该是 |
|---|---|---|---|---|
| A 第 1 次 | 809（`chars_eq`） | 775（`chars`） | −19.1%（按 809） | −22.5% |
| B 第 1 次 | 322 | 269 | −28.4%（按 322） | −40.2% |
| C | 1239 | 1066 | +23.9%（按 1239） | +6.6% |

C 的 88 分因此而来：报告自己写着「期刊上限按**剔除文末文献表**核算，自校验请用
992 字」，而门用的正是它说**不该用**的那个含表折算值。
`writing.py:873-874` 的注释还写着「字数门与体量展示都用它（chars_eq）」——
**注释与实现已经漂移**。这同时是 E4 的成因：模型面对一行里两个字数，只能去反推比值。

### Q4　〔n〕式引注落在正则之外，整族引注判据失明 —— 根因 `writing.py:97`

```python
_CITE_NUM = re.compile(r"\[(\d{1,3}(?:...)*)\]")     # 只认半角 [1]
```

A 正文实有 13 处 `〔1〕–〔4〕`、文献表 4 条，体检却是
`citations=0 / cite_numbers=0 / cite_first_order=[] / has_refs=0 / refs_n=0`。
⇒ 「引注首现序」「正文 ↔ 文献表条数对应」「混用两套引注制」这几条**从未真正跑过**。
`_kernel_verdict` 的 ④ 引注分支也会因此恒判 `cites == 0`。

### Q5　追问不重起草契约，新指令零判据覆盖 —— 根因 `loop.py:4429` / `4475-4483`

```python
if resumed and contract is None and (resume or {}).get("contract"):
    contract = TaskContract.from_dict(resume["contract"])   # 原样继承
...
# 契约**原样沿用**（不重新起草、不改 raw_goal）… 追问只是往同一把尺子下加一条新指令。
```

实测 C 的 5 条 `acceptance` 与 A **一字不差**（连 `target=1000`、`stages=['verify','draft']` 都一样）。
用户新加的「压成两三句 / 别加具体数 / 贴全文」**三条全部没有判据**，门一次放行。
产物碰巧全做到了（1404→1318 字符、新增数值 0、全文贴回），**靠模型自觉，不是门在管**。

### Q6　交付体检只认一份稿 —— 根因 `gate.py:1020-1045` `_draft_text`

`draft_text` 或 `draft_path` **二选一、只取一个文件**。A 交 `讨论-初稿.md` ⇒ 文献表完全不在体检里
（`has_refs=0`）；C 为了把全文贴回 `final`，把正文＋文献表塞进同一个文件 ⇒
`has_refs=1` 但 `refs_n=0`、`chars` 把文献表算进正文。**没有「主稿 + 附表」的分层口径**，
于是 Q3 与 Q4 在 C 里叠加放大。

### Q7　阶段技能是软警告，恒亮告警制造噪音 —— `gate.py:565+` / `gate.py:548-563`

- C 交付时警告「引用核验 → `load_skill(nature-ref-verifier)`、起草写作 →
  `load_skill(nature-writing)` 尚未装载」，**仍然 `passed=True`**。
- 「交付物描述与证据措辞没有交集」在 **5 次交付里亮了 5 次**（A×2 / B×2 / C×1），
  注释自己承认「字面匹配天然脆弱」。一条 100% 恒亮的警告等于没有警告 ——
  与「沉默要被记账」相反，**噪音也要被记账**。

### Q8　两套 id（可用性，伤害最低）

`POST /api/run` 回运行 uuid，产物/历史用时间戳目录；`/api/artifacts?uuid` 回
`exists:false`，`/api/follow` 又只认 uuid。界面历史列表用归档 id 所以真人看得到稿子，
**外部脚本首次必扑空**。

## 4. 查证后明确排除的伪卡点（自我修正）

| 初判 | 复核结果 |
|---|---|
| 工具回包被截断，模型读不到技能全文 | **不成立**。`tools.py:403-415` 的 `truncate` 三场**触发 0 次**，实测 `result_orig_chars == result_chars`。`result_dropped`（A 61,442 字符）只是 `tools.py:35` 的 `RESULT_PREVIEW_CHARS=800` **界面预览**口径差，不是模型侧截断。撤回该归因。 |
| 上下文膨胀是延迟主因 | **证据不足**。A 的 `messages_chars` 与单次 `llm_done.ms` 的 Pearson r 仅 **0.444**（B 0.460 / C −0.039），A 前 3 步均 5.3 s、后 3 步 10.3 s。延迟主要由输出长度与思考量决定（A 第 11/12 步 23 s / 25 s 是长思考）。膨胀确定推高 **token**，不能说成推高 **延迟**。 |
| 缓存命中 95% ⇒ 前缀不浪费 | **不成立**。命中段仍占 input token 40–70%，prefill 仍在，且 `billing=UNKNOWN` 无从核对折扣。 |

## 5. 最先动的三处（按"一处改动解开多条"排序，均不需换模型）

### ① 统一字数量纲，并把体检结果变成模型可调用的工具

- 把 `writing.py:373-375` 与 `gate.py:361-364` 的展示值改成**与 `chars_delta_pct` 同源**
  （`chars_eq`；含文献表时改用 `chars_excl_refs`），修正 `writing.py:873` 的过期注释。
- 把 `writing.lint()` 包成一个工具（或每步把 `Report.brief()` 回灌），让"我现在多少字"
  变成**读回来的数**，而不是模型拿比值外推。
- 同时解开：**Q3 / E4**，并消除 C 的 88 分误判与 `final` 自述数字不准。
- 验收：B 夹具重跑，thinking 里不再出现「让我估算 / 比值 0.685」类手算；
  同一份稿报告中「体量」与「当前」为同一个数。

### ② 追问重起草契约 + 把已量指标接进 `_kernel_verdict`

- `loop.py:4429` 的续跑分支：有 `follow_up` 时，把本轮新约束**并入** `acceptance`
  （保留父轮条款，别整份丢弃），并同步 `target_chars` / `stages`。
- `gate.py:358-407`：接进 `cliche_hits`（对应 A 第 ⑤ 条）、`cite_numbers` /
  `cite_first_order` / `refs_n`（先修 `writing.py:97` 认 `〔n〕`）、`absolutes` / `placeholders`。
- 同时解开：**Q1 / Q2 / Q4 / Q5** —— 这是"判据覆盖面 = 产出上限"的正面修复。
- 验收：C 夹具重跑，契约里能数到 3 条新约束；构造一份含 `〔3〕〔1〕` 乱序 + 一句套话的
  负控稿，门必须报「首现序错 / 套话命中」，而不是靠 `evidence.acceptance` 措辞放行。
  **负控必须打红**，两个方向都量。

### ③ 前缀瘦身 + 追问先脱水再发

- `loop.py:4540` 的 `schemas` 改为**按阶段/契约可刷新**（`_mount` 已有域决策，缺的是随步收缩）；
  `loop.py:4786` 的追问轮在**第 1 次 `llm_call` 之前**先做一次 `context.apply`。
- 同时解开：**E1 / E2**（B 的固定前缀占 70%，C 前两步 145,277 tok）。
- 验收：C 夹具重跑，第 1 步 `messages_chars` 显著低于 117,899，
  且 `tools_schema_chars` 出现多档；A 夹具 `input_tokens` 下降且最终 `verdict` 不降。
- 配套：补全 `pricing` 让 `billing.charged` 不再是 UNKNOWN（E5），否则省了多少没有读数。

> **不建议先动**：换模型、加"更多纪律"文本、调大 `compact_target`。
> 三场的失败形状都不是模型能力问题，而是**工具缺失 + 判据失明 + 口径漂移**。
