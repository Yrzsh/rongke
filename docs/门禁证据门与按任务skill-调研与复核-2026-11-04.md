## 1. 方法：怎么算数

1. **外部**：只用 arXiv `abs` 页最新版与 GitHub README 原文；二手转述只用来找线索，**数字一律回一手核**。
2. **内部**：真跑 `POST /api/run` 三场 → 读 `preset_mounted` / `preset_stages` / `deliver_attempt` / `llm_call`；
   单元判据真调函数、真读回对象，不扫源码字符串冒充「接好了」。
3. **两个方向都量**：「会拦」与「不会在正确的稿子上报错」各要一组正负控 —— 99.6% 与 0% 是同一种失败。

### 2.3 版本陷阱（这轮特意核过）

- **BPS 的二手数字是 v1 的**：v1 摘要写 `0.73 vs 0.20–0.52`、`少 28% token`；**v2 改成 `0.65`、
  `基线需多 28% token 才到 0.60`**。部分聚合站仍引 v1。本报告只认 v2。
- **K-Dense 技能数三个都是真的，但时间点不同**：论文 163（8 月）→ 9 月中博客 166 → 当前 README
  **177**（v2.72.0 移除 4 个从 Anthropic vendored 来的文档技能后剩 177）。不要混用成一个数。
- **2609.00065 自己承认没有任务级评测** ⇒ 「库很全 / 挂上了」**不能**当「质量更好」的证据。
  这与本地实证「14 项门禁指标只证明配置在场、真跑没有一条新指标打红稿子」是**同一类错误**。

### 2.4 四条可执行的校准

1. **按需选择**，不是全量常驻（K-Dense / SkillsInjector / SkillGate 一致）。
2. **token 是硬约束**：选集要带预算（BPS），且要意识到**工具 schema 往往比提示词更大**。
3. **别把「挂上尺子」说成「量出了问题」**：2609.00065 明说无 task-level evaluation。
4. **技能可以帮也可以害**：2610.16238 的 92%→61% 是反面实证，硬门尤其容易把技能变成惩罚。

## 3. 本地审计

### 3.1 门禁：真跑抓到一处真误伤（**已修**）

| | 修前 `03a69c03c26a` | 修后 `06c1c7e6700b` |
|---|---|---|
| 话术 | 同一句「为什么核算字数上限要剔除文献表」，`mode:"answer"` | 同左 |
| 契约 | `mode:"chat"`、`by:"auto"`、内核自述「直接办，不列任务单、不要验收标准」 | 同左 |
| 第一次交付 | **`passed=false`**，`[阶段技能·硬门]` 要求 `load_skill("uncertainty-and-units")` / `load_skill("nature-statistics")` | `deliver_attempt=1`，`hard_rejects=0` |
| 结局 | 第二次 `llm_call` 卡住，176.7s 仍未 `done` | **14.2s / 22 事件 / `success=True`** |

**根因**：上一轮把硬门收窄到「预设点名工序」以免复现 D 场死门，但**没判「本轮有没有一件要走工序的产物」**。
问话契约（`answer_only=True`）没有流水线，装载统计技能全文不改变它答得对不对 —— 判据落在了不存在的对象上。
与 Q1 死门是同族：**加判据前先问「它会不会在正确的稿子上报错」**。

**修法**（`rongke/gate.py` 硬门分支）：`answer_only` 时把硬门降级为 `warnings`（提醒保留、不阻断交付），
真任务 `answer_only=False` 仍按原样硬拦。**拦沉默，不拦选择**。
常驻判据 4 条两个方向：问话不拒 / 问话仍留提醒 / 源码真按 `answer_only` 分流 / 真任务少装 skill 照样拦。

### 3.2 证据门：骨架对，覆盖不全（未根治）

- 九门 1–7 在场、口语约束 100% 进验收；**Q1 已修**：`evidence[].acceptance` 按协议本就该填验收标准原文
  （绑定声明），不是内容字段，现在只判 `shows` / 工具 `result` 是否复述。
- 三个**方向相反**的缺口，如实保留（详见 `docs/论文写作质量与观感复核-2026-11-04.md`）：
  1. **门只量模型粘贴的那一份稿**：D2 落盘 1911 字符含 8 条文献表，`lint` 两次都是
     `has_refs=0 / refs_n=0 / chars=921` ⇒ **100 分是在「只有正文」那份稿上拿的**（Q6 未根治）。
  2. **引注变可数的同时变不可溯源**：`〔库·kb… p.N〕` → `[n]` 且文献表不带页码 ⇒ 锚点正则报 0 处，
     **「读不到」≠「不符合」**；`verify_citation` 从 6/9 次降到 1 次、DOI 全删。用户原话是「别**编** DOI」。
  3. **E2 有 3 处忆档引注**：库内文件在，本场既没 `kb_read` 也没 `kb_search` 命中。
- 证据门**没有一条判据回答「这条 evidence 是否对应最终落盘稿」** —— 这是最该补的一条。

### 3.3 挂载 skill：方向对，装配层不合理（本轮最硬的发现）

| 量到的 | 值 | 判 |
|---|---|---|
| `STAGE_BY_ID` 工序 / 本机 `available()` 技能 | **27 道工序一对一专属技能 / 86 个技能可读** | ✅ 与 K-Dense「一个技能一件事」同向，`stages.py` 开头就记过「五个技能抢同一件事」的旧账 |
| 5 类任务预设的工序 / 技能集合 | `paper-writing=draft,polish` · `lit-verify=search,verify` · `stats-review=stats,units` · `figure=figure` · `deck=slides`，**两两不同** | ✅ 「每种任务所需 skill 不一样」已是真功能，真 HTTP `preset_stages` 事件读得回技能名 |
| `SYSTEM` | **6749 字符 / 145 行，每场全量注入** | ❌ SkillsInjector 点名的 **static all-injection** |
| 其中 PPT 段（`做演示文稿`→`工作区纪律`） | **4077 字符 = 60.4%** | ❌ 纯问答 / 纯写作也整段带着 |
| 首轮现场（`llm_call n=1`） | `tools_available=59`、`tools_schema_chars=**42753**`、`messages_chars=15745` | ❌ 上下文大头是**工具 schema**，不是提示词；baseline `initial_domains` 仍 5 域全挂 |

⚠️ **不能按标题粗暴裁剪**：PPT 段里长着「交稿时必须附上正文全文 `draft_text`」「写作姿态也是体检项」
这些**写作交付必需**的指令（段位置本身是历史错位）。直接按场景丢掉 PPT 段会让写作任务丢掉交付纪律 ——
这正是「判据覆盖面」与「资产布局」两件事要分开处理的原因。

**三处「自称成功」，本轮修了两处、第三处让它说出口**：

| # | 缺陷形状 | 本轮处置 |
|---|---|---|
| a | 只验工序 **id** 存在就全绿，但工序指向的 **skill 是磁盘文件**；客户机缺 `vendor/skills` 或没装 `~/.agents/skills` 时，硬门仍会要求 `load_skill` 一个读不到的技能 | ✅ `load_capability_preset()` 挂载期读 `stages.available()`，缺件直接进 `MountReport.broken`，理由点名工序与技能名 |
| b | `stats-checklist` 在 `stats-review.json` 里躺了两轮，**代码零实现、挂载全绿**（`PromptSections.mount()` 无条件回「追加 N 段」） | ✅ 加提示段白名单（非法名字 ⇒ broken）、定义 `loop.STATS_CHECKLIST` 单源文本、按预设真追加进 system；baseline 逐字节不变 |
| c | `complete:true` 结构性覆盖只配置 / 挂载，未接 `initial_messages` | ⚠️ **未接线，但不再假装**：`provides` 里显式写 `[未接线] complete=true … 当前仍按追加语义执行` |

**还差一层**：工序 → skill 是全局固定表，预设只能选「哪几道工序」，**不能替换某道工序的 skill 实现**。
所以「每种任务所需 skill 不一样」目前严格说是「工序集合不一样」，不是「技能实现可换」。

## 6. 未修 / P4 方案（按优先级，不粉饰）

1. **P4 · 按任务裁剪 system 段**（对应 SkillsInjector / BPS）。前置条件：先把「交稿纪律」「写作姿态」
   从 PPT 段拆出来做常驻段，再给每段标依赖场景，才敢按场景选段。判据必须包括：
   baseline 拼出来**逐字节 == 现 SYSTEM**；每个任务预设的 system **逐条少掉不相关段**；两个方向的正负控。
   **在这套判据落地前不裁剪** —— 否则就是拿 6749 字符的错位资产做手术。
2. **工具 schema 硬预算**：`mount.initial_domains` 已能收窄（figure 预设只挂 3 域）且支持 `per_stage`，
   但 baseline 仍 5 域全挂、42753 字符 schema 无预算。BPS 式「预算下选集」尚未实现。
3. **证据门锚到最终落盘稿**（Q6）：`draft_text` 之外，应量 `write_file` / `draft_path` 指向的真实文件。
4. **`complete:true` 真接线**：现在明确标「未接线」，比假装生效好，但仍是欠账。
5. **工序 → skill 可替换**：预设只能选工序，不能换实现；需要给 `Stage` 加按预设覆盖的能力。
6. **观感旧账**：10 个胶囊默认只露 3 个、`final` 不含文献表、恒亮警告、成本 `UNKNOWN`。
