# 综述写作流程：设计 + 改造（已实施）

> 目标（用户原话拆解）：荣珂收到「写一篇综述」时，按固定流程走完，**一次成稿、不返工**。
>
> 期望流程：
> ① 先判库里文献够不够 → ② 不够才检索入库 →
> ③ 挂 PaperSpine 敲定大纲（每章内容 + 该章引用哪些文献）→
> ④ **先按大纲绘图**（防止后面遗漏）→ ⑤ 按阶段 skill 分章写作 →
> ⑥ 一次拼装检验。
>
> 用户点名要避开的坑：**多次返工产出的一般很垃圾**。
>
> 用户对实现方式的裁决：**「工具肯定还是他自身携带的好，毕竟是要作为商业化工具的」**
> —— 所以能力全部长在荣珂自身内核里，不依赖用户机器上的外部项目。
> 第一节的缺口分析保留原样（那是改造依据），第三章起改为已实施的记录。

### 1.2 五个真缺口（每个都有代码位置）

#### G1 · 阶段顺序是反的：`figure` 排在 `draft` 之后

`rongke/stages.py:103` 起，`STAGES` 元组的顺序就是流水线顺序：

```
0 discipline  1 plan  2 search  3 fulltext  4 read  5 translate  6 cite
7 verify  8 draft  9 polish  10 stats  11 figure  12 data  13 review ...
```

`stages.py:144` 的 `figure`（配图）在索引 11，`stages.py:133` 的 `draft`（起草）在索引 8。
`plan_text()`（`stages.py:219`）明确写着「**顺序即流水线顺序**」并逐条编号念给模型听，
`contract.py:237-239` 还追加一句「不要边写边润色，也不要跳过起草直接润色」。

⇒ 模型现在收到的指令是：**先写稿，润色完，再配图**。这与你要的「先图后文」正好相反。

#### G2 · `fulltext` 阶段不会被推断出来

`stages.py:118-120`：

```python
Stage("fulltext", "全文获取", "nature-downloader",
      ("下载全文", "获取全文", "知网", "全文获取", "下载文献"),
      "合法拿到全文与附件"),
```

`infer_stages()`（`stages.py:206`）是**纯关键词命中**。「写一篇……文献综述」这句话里
一个触发词都没有 ⇒ 上一轮 `fulltext` 阶段确实没被推断出来，nature-downloader 从未被要求装载。

#### G3 · ★ nature-downloader 挂上了也**根本跑不了**——荣珂没有 shell 工具

这是最硬的一条。实测 `Rongke()` 装配后的完整工具面（59 个）：

```

         report_blocker subagent verify_citation write_file
figure(5) kb(12) ppt(7) research(21) topic(5)
```

**没有 exec / shell / run_command / bash 任何一个。**

而 nature-downloader 的入口是 `scripts/batch_download.mjs`（Node ESM，36KB），
配套 `configure_school.py` / `configure_credentials.py` 是 Python 脚本。
荣珂既没有 shell、也没有"跑一个 node 进程"的工具 ⇒ **即使把 skill 全文喂给模型，
它也没有任何办法执行下载器**。它只能退回到 `kb_add(src="doi:…")`，
而那条路走的是 litkb 自带下载器。

litkb 自带下载器的真实能力（`~/.dsh/papers/workbench/litkb.py:632` `_try_download_oa_pdf`）：

```
① Unpaywall 给的出版方 PDF 直链 → ② doi.org 内容协商 → ③ Sci-Hub（默认关/现为开）
```

**没有 Europe PMC `fullTextXML` 这条路**（整份 litkb.py grep `europepmc|fullTextXML` = 0 命中）。
这正是上次全流程「新增 15 篇只拿到 3 篇全文（20%）」的根因 —— 多数是**路由缺一条**，
不是世上没有开放版。这条已记在 `learned-pitfall-rongke-lit-download` 里。

#### G4 · 代码里**不存在**「库里文献够不够用」这个判定

全仓 grep `够用|够不够|suffic|coverage` 在文献语料上是空集（命中的全是 bill金额、

⇒ 你要求的第一步（先判够不够）目前在荣珂里**没有对应实现**，模型只会凭感觉走。

#### G5 · 首次使用配置里没有「检索/下载」这一项

`setupdoctor.py:626-636` 的 `CHECKS` 九项：

## 二、设计：综述七步流水线（S0–S6）

核心原则：**前面把结构定死，后面只做填充**。返工之所以产生垃圾，是因为结构和内容
在同一遍里来回改；把「大纲 + 章-文献映射 + 图表清单」前置冻结，写作阶段就只剩
"按已定结构把段落写出来"这一件事。

| 步 | 名字 | 输入 | 产出（落盘） | 机器判据（过不了不许进下一步） |
|---|---|---|---|---|
| **S0** | 库够用性判定 | 用户题目 | `coverage.md` | 每章主题词在库里的命中：章覆盖 ≥K 篇不同文献；题目核心 5–8 个论点每个 ≥1 条段落级命中 |
| **S1** | 检索入库（**按需**） | S0 的缺口清单 | 库新增条目 + `search_log.md` | 缺口清单里每一条都走完 检索→取全文→入库；**入库成功按 `texts/`+`pdfs/` 实物判**，不按总结措辞 |
| **S2** | PaperSpine 大纲冻结 | 库 + 题目 | `contribution.md` + `outline.md` + 章-文献映射 | 每章有：一句话论证、要引的 doc_id 清单、该章目标字数；总数对得上 `target_chars` |
| **S3** | **先出图表** | S2 大纲 + 章-文献映射 | 图表清单 + 已绘制的图 + `audit_figure` 报告 | 每一章都有对应的图表条目（"该章无图"必须显式写明理由）；图面体检报告新鲜 |
| **S4** | 分章写作 | S2 大纲 + S3 图 | 每章一个文件，逐章落盘 | 每章：引用的 doc_id ⊆ 该章映射清单；字数在分配预算 ±20% |
| **S5** | 拼装 | 各章 + 图 | 综述.md（单篇） | 引注首现顺序递增、编号连续、章序与大纲一致 |
| **S6** | 一次检验 | 综述.md | 检验报告 | 写作体检 + 引用核验（`verify_citation`）+ 图面门 + **参考文献 ≥50 篇**，**一轮出结论** |

### 文献下限：综述至少 50 篇（2026-10-24，用户追加）

这条要求落到**三个位置**，而不是只在交付时判一次：

| 位置 | 形态 | 为什么在这里 |
|---|---|---|
| `contract.outline_kickoff_text()` | 冻大纲时就摊开"总数 ≥50，摊到 5–7 章每章 8–10 篇" | 交付时才算账 ⇒ 发现少 20 篇 ⇒ **一次完整返工**。大纲阶段就知道每章该有几篇，补文献和改结构是同一件事，只做一遍 |
| `writing.py` 的 `refs_n` | 数文献表条目数 | 原来只有 `has_refs`（0/1）—— 列 3 条也算合格。**有判据和没判据在这里是一回事**，所以先补度量 |
| `gate.py` 第 7.5 条 | 综述 + 长稿 ⇒ `refs_n < 50` 打回 | 唯一的硬门 |

三个刻意的收窄，都是为了不让这条门变成"逼模型变差"：

1. **只对综述**（`_is_review_like`）。一篇原创研究稿引 30 篇是正常的，套 50 篇会
   逼模型堆无关引文 —— 那是"为了过门而变差"。
2. **只对长稿**（`_is_long_review`，≥5000 字）。「写一段综述性文字」不该被要求 50 篇。
3. **数不出来就只警告、不拦**。文献表格式不认识时 `refs_n` 会是 0，
   这时罚模型等于罚"我读不懂"。宁可不管，也不许因为数不出而拦 —— **不出数，不出假数。**

`refs_n` 的计数方向也是刻意选的：只数**文献表里的条目行首**
（`[1]` / `1.` / `- ` / APA 括号年份），**不数正文里的 `[1]` 引注**。
数引注会让同一篇被引三次算成三篇 —— 那比数不出来更糟（用户以为 50 篇达标了，实际 18 篇）。
GB/T 7714 的长条目折行不计入，是"只会少数、不会多数"的方向，与本条要求同向。

### S0 怎么机械化（关键，不能靠模型感觉）

用**已有的工具拼**，不新建索引：

1. 让模型只做一件窄事：把题目拆成 5–8 个论点 + 每章主题词（纯文本，可复核）。
2. 对每个主题词调 `kb_search`（**词长 ≥3 字或英文**——litkb 的 trigram 索引会静默丢弃
   所有两字词，这是已复现的坑，含"融合/温度"这类常见两字词）。
3. 机械统计：每个主题词的 `hits[].doc_id` 去重数、命中段落数。
4. 判定（建议阈值，可调）：
   - 单章 `distinct_docs < 3` ⇔ **该章文献不足**
   - 某个核心论点 0 命中 ⇔ **硬缺口**
   - 任一命中 ⇒ 记录 doc_id，作为 S2 章-文献映射的种子
5. 全部达标 ⇒ **跳过 S1**（这就是你要的"够用就不检索"）；有缺口 ⇒ S1 只补缺口，不全量重检。

这一步的价值：把"够不够"从感觉变成一张表，而且**同一张表直接变成 S2 的映射输入**，
前置信息只算一次。

### S1 最终怎么做的（与当初三个方案的差别）

当初摆出三条路，最后**都没照着走**，因为用户加了一条约束：
**「工具肯定还是他自身携带的好，毕竟是要作为商业化工具的」**。

| 原方案 | 结局 |
|---|---|
| A · 给内核加通用 shell 工具 | **否决**。对商业化产品是负资产；并且等于把"能执行任意命令"交给模型 |
| B · 只补 litkb 里那条 Europe PMC 路 | **做了，但没只做这一条**。补 `litkb` 需要动 workbench 那边的第三方代码；而荣珂需要的是**自己的**能力，于是这段逻辑写进了内核新模块 `rongke/litfetch.py` |
| C · 加受约束的 `literature_fetch`，壳内调 nature-downloader 的 node 脚本 | **工具名留下了，壳换了**。`literature_fetch` 存在，但它**不调 node、不调外部项目**，三条路全在 `litfetch.py` 里用标准库实现 |

为什么 C 的做法被换掉：nature-downloader 依赖 node 与 12 个 npm 包，
而它真正做的事（按 DOI 取 OA 全文）用标准库 300 行就够。多一层运行时依赖，
对一个要卖出去的产品是纯成本；而且用户机器的 node 版本、npmmirror 配置、
防火墙策略都会变成新的"配不好就用不了"。

保留的仍然是当初列的三条纪律，一条没少：

1. 拿不到就**如实报缺哪条路**（Europe PMC / Unpaywall / doi.org / CNKI），
   不许写成"世上没有" —— 这条写进了 `litfetch` 的错误文案与单测。
2. 入库不按总结措辞判，按 `texts/<doc_id>*` 与 `pdfs/<doc_id>*` 的**实物**判 ——
   `fulltext=true` 只代表"抽出了文本"，原件可能早没了。
3. 中文（CNKI）另走一条链：它需要**已登录的浏览器**，内核如实说明走不了，
   不假装支持（`setupdoctor` 的 `lit.cnki` 那条就是干这个的）。

## 三、实施记录（已落地的部分，逐项写清落在哪）

### 3.1 新增两个内核模块（只用标准库）

| 模块 | 干什么 | 为什么是新写的 |
|---|---|---|
| `rongke/coverage.py` | 回答「库里的文献够不够写这篇」 | 全仓过去**没有这一句话**。`kb_list` 只报"有哪些篇"，不回答"够不够覆盖这个题目" |
| `rongke/litfetch.py` | 取全文，三条路 | 原下载器只有 Unpaywall → doi.org → Sci-Hub，**没有 Europe PMC fullTextXML**（`grep -i europepmc` 在 `litkb.py` 命中 0）。这是 20% 成功率的真根因，不是反爬 |

`coverage.assess()` 的判据（可机械复算）：

- `docs == 0` ⇒ **硬缺口**（这一章在库里一个字都没有）
- `0 < docs < 3` ⇒ **薄**（有，撑不起一节）
- `docs >= 3` ⇒ **够**
- **一条硬缺口不许被"其余都够"抵掉** —— 这是刻意的方向，防"平均值过关、某一章空着"

★ 两处实测踩到的细节，写进了代码注释：

- 两字中文词（融合/温度/酶解）会被 litkb 的 trigram 索引**静默丢空**，回的结果和"库里真没有"
  长得一模一样。⇒ `_dropped_note()` 把它们**单列出来**，并明说"不能当作库里没有"。
- 空输入判「**无从判断**」而不是「库不够」。把"没给主题词"读成"库里没有"，模型就会白搜一轮。

`litfetch.fetch_one()` 三条路顺序：Europe PMC fullTextXML → Unpaywall OA 直链 → doi.org 内容协商。
判定用**正文字符数**（≥1200）而不是 `%PDF` 魔数 —— 判"有没有拿到能读的东西"，不判"有没有拿到文件"。
失败时错误文案必须写清「**这三条路这次没成**，不是世上没有开放版」，防止模型把"我没拿到"当成事实结论。

### 3.2 两个新工具（都进 `core` 域）

| 工具 | 参数 | 为什么进 core |
|---|---|---|
| `kb_coverage` | `topics[]` / `min_docs` / `min_ok_ratio` / `per_topic` | 它是**流程第一步**，不能因为"没装文献库装备"就用不了 |
| `literature_fetch` | `dois[]` / 相对 `out_dir` | 同上；`mutating=True`，落盘走围栏 |

★ `kb_coverage` 在**进程内**调 workbench 的 `kb_search`（`bridge.py` 反射），不起子进程。
参数被收窄到「只有主题词与两个阈值」—— 这是"给模型一个受约束的动作"而不是"给它一个 shell"。

### 3.3 阶段顺序（`stages.py`）

```
0 discipline  1 plan  2 search  3 fulltext  4 read  5 translate  6 cite
7 verify  8 outline  9 figure  10 draft  11 polish  12 stats  13 data ...
```

两处相对原来变了：

- **`figure` 从 `draft` 之后挪到之前** —— 对应「先按大纲绘图，防止后面遗漏」
- **新增 `outline` 阶段**（挂 `paper-spine`），在 `figure` 之前 —— 结构必须先冻结

`plan_text()` 里加了两段条件纪律：`outline` 在阶段表里时讲「结构冻结纪律」，
`figure` 与 `draft` 同时在场时讲「先图后文纪律」。

### 3.4 契约推断（`contract.py`）

新增 `_derive_review_shape()`：

- `_is_review_like`：目标里有「文献综述/综述/review article/研究进展/研究现状…」且是写作任务
- `_is_long_review`：`target_chars is None or >= 5000`
- 长综述 ⇒ `needs_kb = True`、`needs_figure = True`（除非明说「不用配图」）

`_ensure_review_stages()` 在长综述时补三个阶段（`fulltext` 在 `search` 后、`outline` 在 `draft` 前、
`figure` 在 `outline` 与 `draft` 之间），**且保留用户显式给的顺序**。

★ 这个形状闸门（`>=5000` 字）是必需的，不是保守：`figure_test.py` 与 `deck_test.py`
里有反向对照断言「写一篇 1200 字综述」**不许**被当成图任务/PPT 任务。
把「综述」直接塞进 `_FIGURE_STRONG` 会让那两条断言当场失守 —— 短综述硬配图也是错的。

`to_prompt()` 里插入两段开工动作：`fulltext_kickoff_text()`（长综述时）与
`outline_kickoff_text()`（长综述时）。两段都写成**带序号的步骤**，
因为本仓反复验证过：模型执行的是它读到的**动作**，不是它读到的**要求**。

#### 3.4.1 一个"定义了却没人接线"的真 bug（2026-10-24）

**症状**：`TaskContract(raw_goal="画一张融合机制示意图")` 出来 `needs_figure=False`、
`stages=[]` —— 一个**明确的画图任务被判成不要图**。后果是连环的：

1. `figure` 域工具不挂载 ⇒ 模型手里根本没有绘图工具；
2. 图面纪律段不注入；
3. 交付时图面门不启用；
4. 阶段推不出 `figure`。

**根因**：`needs_figure` 只是 dataclass 的默认 `False`，`__post_init__` 过去
**从不用 `_looks_like_figure` 填它** —— 只有综述那条分支会置位。
而 `_looks_like_figure()` 本身**一直是对的**（"画一张/示意图"都在词表里）。

⇒ 这是本仓最反复的一类缺陷：**函数定义对了，没人调用它。**
表现是"看起来什么都在，就是不起作用"。**只测 `_looks_like_figure()` 会全绿**，
必须端到端测"契约吃到了没有"。

**修法**：在 `__post_init__` 开头按 `_looks_like_figure` 派生，位置必须在
`_derive_review_shape()` **之前**（补阶段要用 `needs_figure`）。
只在没人显式给值时才派生 —— 调用方传进来的 `True` 是权威。

**修完当场撞出的第二个 bug**：派生提到前面以后，`needs_figure` 先被关键词置成 `True`，
于是综述分支里那句「明说不要图就别置位」**再也不会执行** ——
「写一篇……文献综述，不用配图」被判成要图。

⇒ 根因是**同一份判据写在两个地方**。修法是把它抽成 `_RE_FIGURE_VETO` 正则 +
`_user_vetoed_figure` 属性，两处共用一份定义。
（这个仓已经因为"一个口径手抄两份"吃过不止一次亏。）

### 3.5 交付门（第 10 条，`gate.py`）

判据挂在「契约的阶段列表里有 `outline`」上，**不是**挂在 `_is_long_review` 上。

- 需要：工作区里有大纲文件（文件名含 `outline` / `大纲` / `提纲`，取最新那份）
- 需要：能读出 ≥2 个章标题
- 需要：**每一章**至少绑 1 个 doc_id（`kb…` 形态或 DOI 形态）
- 不需要：doc_id 对不对（那是 `verify_citation` 的活）、措辞好不好

★ 为什么挂在阶段而非形态：用户可以用预设/参数**显式固定**阶段。显式没给 `outline`
却仍按大纲门拦，等于无视用户的明确指定，还会造出「根本没被要求写大纲、交付却永远过不去」
的死路 —— 那就是本仓记过的「不可能通过的门」。

★ 开发过程中修掉的两个真错误（都写进了注释）：

1. 切片起点用了正则匹配的 `start()`，让匹配吃掉了 `## ` 与标题文字，于是「第一章」那一段里
   装的是第一章正文**加上第二章的标题**，数出来的是第二章的 doc_id。症状：两章都写了 doc_id，
   却报「2 章没有绑定文献」。
2. 没摘掉文档标题 `# 综述大纲`，于是每份规范写法的大纲都稳定多出一个"0 篇文献的章"，
   门永远打不开。修法是：一级标题且拿掉它之后还剩 ≥2 个标题时，才当文档名摘掉
   （只有一级标题当章的大纲也是合法写法，那种情况必须保留）。

## 五、与"不要返工"的对应关系

荣珂的证据门是**打回式**的。你说「多次返工出来的一般很垃圾」，对应的机器形态是：
**把可判定的事全部前置成"进下一步的门槛"，而不是"出稿后的打回"。**

这次改造的每一处都是按这个方向落的：

| 原本会在哪里返工 | 现在前置成什么 |
|---|---|
| 写到第三节才发现某章没文献 | `kb_coverage` 判硬缺口 ⇒ 补到 `need_more_literature=false` 才进大纲 |
| 写完发现全文其实没下到 | `literature_fetch` 按正文字符数判，不是按"有个文件"判 |
| 写完发现配图漏了三章 | `outline.md` 每章必须写「本章图表」或「本章不配图，理由：…」 |
| 写完发现章节结构和导言对不上 | 大纲门：`outline.md` 没落盘 / 章没绑 doc_id ⇒ 交付被拦 |
