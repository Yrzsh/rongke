# 导师模式：让荣珂从「交付机」变成「陪跑机」

> 2026-09-22 · 本文全部结论基于**当天实测**（命令与回显见 §1），不含推测。
> 起因：用户提出「这个 agent 还要起到一个作用，就是老师」——查文献 / 定课题 / 推计划 / 解卡点 / 开题报告。

---

## 1. 实测证据（先看事实，再看结论）

| # | 量了什么 | 怎么量的 | 结果 |
|---|---|---|---|

## 2. 诊断

### 2.1 一句话

> 荣珂是一台**交付机**（时间尺度 = 一次 run）；「老师」是一台**陪跑机**（时间尺度 = 一个学期）。
> 导师的四个动作里，**三个需要跨会话的连续性**，而这正是荣珂现在没有的东西。

### 2.2 四件事 × 现状

| 导师的动作 | 荣珂现状 | 判定 |
|---|---|---|
| **查文献** | `literature_search`(四源元数据) · `web_search` · `fetch_doi` · `build_references` | ✅ 强 |
| **读文献 / 建知识库** | 技能有（`nature-paper-card` / `nature-reader`），**库也在**（10 篇真文献 + 全文 + FTS5 段落级索引），但 **agent 一篇都读不到** | ❌ **能力缺口** |
| **定课题 / 推计划** | `plan` 阶段 + `evidence-graded-research-protocol` 技能（**证据分级**，很强）—— 但「计划」是**一次性文本**，不是一个可以「下次接着看」的对象 | ⚠️ **半个** |
| **解执行中的卡点** | **完全没有**。`report_blocker` 是终局动作，不是可追踪对象 | ❌ **零** |
| **开题报告** | `proposal` 阶段 + `nature-proposal-writer`（状态机 + `research_canon` + `evidence_table`） | ✅ 强，但**证据表只能手抄** |

### 2.3 最硬的一条

用户说「**知识库模块也是极为重要的一环**」—— 而实测：**它已经存在，却对 agent 完全不存在。**

这与 2026-09-21 那个 `read_file` 事故是**同型复发**，连形都一模一样：

> | | read_file 事故（09-21） | 知识库（今天） |
> |---|---|---|
> | 外部能力 | `literature_search` 能搜全网 | `literature_search` 能搜全网 |
> | 本地资产 | 材料区有 md，**没有工具能读本地文本** | 有 10 篇真文献 + 全文 + 索引，**没有工具能碰** |
> | 模型的反应 | 撞 31 次调用想尽办法读材料 | （还没走到，因为压根没有这个工具）|
> | 修法 | 补一条基元 `read_file` ⇒ 13 张幻灯片出来了 | **补一组基元 `kb_*`** |

**通用那一问（第三次应验）**：
> 「这件事，我给了它**工具**吗？」—— 不是"我告诉它该怎么做了吗"。

### 2.4 三个结构缺口

| # | 缺口 | 形状 | 为什么致命 |
|---|---|---|---|
| **G1** | 知识库不可达 | **能力缺口** | 没有它，「基于真实文献」这句话**无法被验证** —— 模型只能靠上下文回忆自己读过什么 |
| **G2** | 课题不是一等公民 | **缺对象** | 一次 run 结束，课题就消失。导师最基础的「上次到哪了」问不出来 |
| **G3** | 卡点无法被记账 | **缺台账** | 一个卡点只被说一次，**永远不会第二次出现在模型眼前**。同一个坑换个说法再踩一次，系统不会提醒 |

**主次**：G1 是**源头**。G2/G3 是让 G1 里的东西**沉淀下来**的容器。G2/G3 没有 G1 就是空壳（台账里没东西）；G1 没有 G2/G3 就是一次性检索（查完就忘）。**要一起设计，但落地有先后。**

## 3. 设计

### 3.1 总体形状

```
┌─────────────────── 知识底座（唯一真相）───────────────────┐
│  litkb  : 10 篇真文献 / 全文 / FTS5 段落级索引（已有，未接线）│
│  litmap : 聚类 → 研究缺口 find_gaps（已有，未接线）          │
└──────────────────────────┬───────────────────────────────┘
                           │  ◀── P0 在这里接线（当前断点）
┌──────────────────────────▼───────────────────────────────┐
│  课题（一等公民，跨会话存活）                                │
│  TOPIC.md · PLAN.md · READING.md · BLOCKERS.md · EVIDENCE.md│
└──────────────────────────┬───────────────────────────────┘
                           │
      选题 ──→ 计划 ──→ 执行（卡点闭环）──→ 开题报告
       P1      P1        P2                 P3
```

**一句话**：知识库**不是第四个功能，它是整条链的源头**。有了「读进来的东西」和「卡过的点」留了痕，开题报告才是**水到渠成**（把已有的痕整理成文），而不是**从零手抄**。

### 3.2 P0 · 知识库接线（源头）

**工具族**（建议落在 `workbench_mcp.py`，`litkb`/`litmap` 本来就在那儿）：

| 工具 | 签名 | 给模型回什么 | mutating |
|---|---|---|---|
| `kb_list` | `(status="", tag="", limit=50)` | 紧凑清单：`id / 年 / 标题(60字) / 全文有无 / 状态` | False |
| `kb_search` | `(query, mode="para", n=8)` | **段落级**命中 ＋ `doc_id` ＋ **页码** ＋ 文档出处 | False |
| `kb_read` | `(doc_id, page_from=0, page_to=0, max_chars=6000)` | 正文片段，**如实报全文总长与截断** | False |
| `kb_gaps` | `(query, n=10)` | `litmap` 的聚类 ＋ **未覆盖缺口** | False |
| `kb_ask` | `(question, ids=[], n_docs=3)` | AI 问答，**每条带页码出处** | False |
| `kb_add` | `(src, tags=[])` | 入库（pdf / `doi:` / `arxiv:`） | **True** |
| `kb_note` | `(doc_id, text)` | 记笔记 | **True** |

**三条设计约束（都来自本项目已有的实测教训）**：

1. ★ **回给模型的是紧凑文本，不是原始 JSON。**
   实测 `litkb.search_docs()` 单条结果就带**整篇 abstract**（含 `<jats:p>` 标签，≈1800 字符）。
   8 条一起回 = 15k 字符 —— **一次检索就把上下文烧掉**。
   ⇒ 复用 `figure.py`「工具返回紧凑 JSON」与 `deck.format_for_model()` 的做法；
   **并且截断必须如实说**（M 型：不许把"没给全"渲染成"就这么多"）。

2. **新开一个域 `kb`，不塞进 `research`。**
   `research` 在 `_MOUNT_ALWAYS` 里 ⇒ 加进去等于给「写一段引言」也送一套知识库 schema，
   **每场任务都付这笔钱**。应当由 `mounting_decision` 按信号挂
   （信号词：`文献/知识库/读过的/之前那篇/课题/读书`）。
   ⇒ **安全不变量**：`needs_kb ⇒ kb_* 必在 allow 里`（照抄 `needs_deck ⇒ audit_deck`）。

3. **写类工具（`kb_add`/`kb_note`）必须走"写完独立复测"** ——
   `litkb` 有 `library.json` ＋ SQLite 两处真相，写完要**读回来核**，
   自述不算证据（`apply_professional_theme` 那个假成功是活教材）。

### 3.3 P1 · 课题是一等公民

| 件 | 内容 |
|---|---|
| **新阶段 `topic`** | 排在 `plan` **之前**、`discipline` 之后。触发词：`课题/我的课题/研究方向/开题/这个项目` |
| **长生命工作区** | `课题/<slug>/`（**不是** `runs/<id>/`；后者是任务，前者是课题） |
| **五份活文档** | `TOPIC.md`(题目/科学问题/假设/边界) · `PLAN.md`(里程碑/每步判据/依赖) · `READING.md`(读过的：从它拿到什么/和课题什么关系) · `BLOCKERS.md`(卡点台账) · `EVIDENCE.md`(证据表) |
| **跨会话续跑** | **不新造机制**。复用 `loop.py` 已有的快照/续跑，把「**这个课题到哪了**」写进 `initial_messages()` —— 这与 `workspace_listing_text()` 是**同一条定律**：「这个事实，模型有办法自己得到吗？」得不到的，就是内核必须提供的 |

### 3.4 P2 · 卡点台账（★ 导师最核心的价值）

**现状的病灶**：`report_blocker` 是**终局**动作。所以一个卡点**只被说一次**。

**新机制（与 `report_blocker` 分工明确，不是替代）**：

| 工具 | 语义 | 收工吗 |
|---|---|---|
| `report_blocker`（已有） | 我**干不成**，如实收工 | 是 |
| `raise_blocker`（新增） | 我**卡在这一步**，记账，继续 | **否** |
| `resolve_blocker`（新增） | 这个卡点**怎么绕过去的** | 否 |

**★ 判据（整个设计的灵魂）**：
> **新任务开工时，若历史卡点里存在"未闭环"且与本次目标相似的一条，
> 内核必须在第一条消息里摆出它，并附上"当时试过什么"。**

配套正控/负控（照本项目惯例，两边都要量）：
- **正控**：造一条 open 卡点 ⇒ 起一个相似目标的新任务 ⇒ 首条消息**必须**含该卡点的 `tried` 内容；
- **负控**：把卡点状态改成 `resolved` ⇒ 首条消息**必须不含**；
- **承重自检**：把相似度判据换成恒假 ⇒ 正控**必须当场失守**（证明拦截确实来自它）。

这条把「导师记得你上次卡在哪」从**愿望**变成**可测行为**。

### 3.5 P3 · 开题报告（水到渠成）

`nature-proposal-writer` 已经很强（状态机 + `research_canon` + `evidence_table`）。**缺口只有一个**：

> `evidence_table` 现在只能**手抄** —— 模型从上下文里回忆自己读过什么。

有了 P0–P2，`evidence_table` 应当**从知识库 + `READING.md` 直接生成**：
- 每一条 = `doc_id` ＋ **页码定位** ＋ 它支撑哪一句
- **★ 判据**：开题报告里的每条引用，**必须能在知识库里按 id 找到**（不许有库里没有的引用）。
  - 这与既有的 `nature-ref-verifier`（引用核验）是同一条精神，但锚点**更硬**：
    **从「联网核验真伪」升级为「本地可复算」** —— 不依赖网络，随时能重算。

### 3.6 卫生项（顺手）

`~/.zcode/skills` / `~/.dsh/skills` 等**第二技能根**里还躺着 4 个被淘汰的写作技能
（`scientific-writing` 29.8KB / `paper-spine` 21.7KB / `write-scientific-manuscript` /
`paper-staged-gen`）。它们**没被映射到任何阶段，但仍在 `index()` 里 ⇒ 模型可以
`load_skill` 装载它们**，绕过 `stages.py` 开头宣称已建立的「1:1 独占」。
⇒ 处置：**挪出技能根**（`_tkit.stash`，挪不是删），**不要**加豁免名单。

## 4. 落地顺序与工作量

| 序 | 做什么 | 动哪些文件 | 荣珂改动 | 判据 |
|---|---|---|---|---|
| **P0** | 知识库接线 | `workbench_mcp.py`（+7 工具）· `bridge.py`（域映射）· `loop.py`（`_KB_DOMAIN`＋挂载信号） | 小 | `kb_test.py`：紧凑文本上限 / 截断如实 / 页码可回溯 / 挂载不变量 |
| **P1** | 课题工作区 | `loop.py`（首条消息）· `contract.py`（课题交代）· `stages.py`（`topic` 阶段） | 中 | 「课题到哪了」必须出现在首条消息；无课题时**不许出现空壳段落** |
| **P2** | 卡点台账 | `loop.py`（两个新工具）· 新 `blockers.py` | 中 | 正控/负控/承重自检（见 §3.4） |
| **P3** | 开题接线 | `contract.py`（proposal 阶段纪律）· `gate.py`（引用可本地复算） | 中 | 库里没有的引用**必须打回** |

**纪律（照本项目惯例）**：改任何公共模块前先 `snapshot.py save`；
改完 `py_compile` 两遍（3.12 ＋ 3.13）；回跑 `regress.py`；
**改 `rongke/*.py` 或 `index.html` 后必须先重启控制台**，否则 `ui_shot` rc=2 拒拍。

## 5. 明确不做的事（写下来，免得下一个人加回来）

| 不做 | 理由 |
|---|---|
| ❌ 重写 `litkb` / `litmap` | 它们是**领域资产**，荣珂只编排、不重写（与 `figure.py` / `deck.py` 同一条纪律）。重写 = 两处真相 |
| ❌ 把知识库塞进常驻域 | schema 是**每场任务都付**的钱（实测 67 工具 = 51,082 字符）。按需挂载才是既有设计 |
| ❌ 给卡点做「自动闭环」 | 谁闭环、怎么闭环，是**人的判断**。内核只负责**让它浮现** + **记账**，不替人宣布解决 |
| ❌ 把「未闭环卡点」做成硬门 | 它该拦的是"**沉默**"（没浮现 = 没提醒），不是"没解决" —— **拦沉默，不拦选择** |
| ❌ 用「知识库里没有」当缺文献的信号 | 库是**私人收藏**，不是全量。没有 ≠ 不存在（这正是本项目 P2 待办里那条「缺图应降级为声明制」的同型错误） |

---

## 6. 一句话收束

> 现在的荣珂能**替你把事做完**；导师模式的荣珂要能**陪你走完一段路**。
> 差别不在模型，在**它手上有没有那几件工具**、**它记不记得上一次**。
> 而这两件事，**都只能长在内核里** —— 写进提示词是不算数的。
