# 插件化边界与外部能力吸收 · 调研、判定与落地

**日期**：2026-11-05　|　**触发**：「现在荣珂是全部由插件构成吗？如果是的话，那还能吸收其他 agent 的长处吗？」
**方法**：不采信文档自述与测试绿灯，只读回代码 + 反事实实证 + 真 HTTP 归档。
**权威证据**：`_realp/caps_ext_test.log`、`_realp/caps_ext_http.log`、`_realp/out/caps_ext_*.json`、`_realp/regress_final7.log`

---

## 0. 两问两答

| 问题 | 结论 |
|---|---|
| **荣珂现在全部由插件构成吗** | **不是。** 是「**硬编码骨架 + 可替换插槽**」：两套插件系统并存且互不调用；6 个内核文件里 3 个 `caps` 零命中；能力消费点只有 **18 行 / 8 个写死行 id**；`SYSTEM` 6749 字符、27 个 Stage、7 条门禁规则全是代码常量。 |
| **还能吸收其他 agent 的长处吗** | **能，而且本轮已经打通了一半。** 落地前「文本」与「工具」两类都要改内核；落地后「丢一个 `.py` + 预设点一行」即可，端到端真跑 14/0 验证。**另一半（新判据 / 新工序 / 装配规则）仍需改内核** —— 瓶颈不在 SPI 种类，在消费点数量。 |

一句话：**插件化做到的是「换行为 = 换预设」，没做到的是「加行为 = 加插件」。** 前者已成立，后者本轮只开了两个口子。

## 1. 事实核查：骨架有多硬

### 1.1 两套系统并存，互不调用

| 系统 | 装配点 | 扩展点 |
|---|---|---|
| 老 `rongke/plugins.py` | `loop.py:3326-3329` | 4 个：`tools()` / `chart_kinds()` / `legend_templates()` / `on_load()`（`plugins.py:105-122`） |
| 新 `rongke/caps.py` + `caps_builtin.py` | `loop.py:3349-3368` | `KINDS` 8 类（`metric/gate/contract/mount/context/tool/prompt/stage`）、9 个内置能力 |

`caps.py:4-9` 自己写明「两条路，不许合并」；实测互相调用 **0 处**。生产 `load_capability_preset()` 直接调用 **3 处**（`loop.py:3357/4262`、`caps.py:561`）。

### 1.2 内核硬编码残留（可数）

| 项 | 数字 | 位置 |
|---|---|---|
| 6 个内核文件里 `caps` 零命中的 | **3 个** | `contract.py` / `stages.py` / `bridge.py` |
| 真正读能力值并作用于行为的消费点 | **18 行 / 8 个写死行 id** | `loop.py` 9、`gate.py` 7、`writing.py` 2 |
| `SYSTEM` 全量注入 | **6749 字符 / 145 行，每场** | `loop.py:51-185`，`:590` 原样取用 |
| 阶段→skill 硬映射 | **27 条 `Stage(...)`** | `stages.py:136-320` |
| 门禁规则表硬编码 | **7 条** | `gate.py:94-102` `_EXTRA_RULES` |
| 其它写死常量 | `NUDGE`/`WRAPUP`/`PRESSURE`/`STATS_CHECKLIST`/`_CHARS_TOLERANCE`/`_REVIEW_MIN_*` | `loop.py:192-222`、`gate.py:177`、`contract.py:121-131` |

### 1.3 预设的表达边界

7 份随库预设共 **35 行 `plugins[]`**，`name` 全是 9 个固定注册名之一：

- `stages` 键存在，但 `preset.py:154-156` 强制 `st ∈ STAGE_BY_ID`，只能在 27 个硬编码工序里**选**；
- `tools` / `prompt` 顶层键**不存在**；`preset.py:212` 明写「提示文本住代码里，预设只点名，不许自带散文」；
- `config` / `mount` / `exemplars` / `tier` 四个键生产零消费。

⇒ **预设 = 开关 / 调参 / 从固定池选工序；引入新行为 0 处。**

### 1.4 反事实实证（这比读代码更硬）

新进程里 `_REGISTRY` 初始为空（`caps_builtin` 是 lazy import）：

```
不 import 外部模块 → resolve('@external/intent-guard') -> None   ⇒ 预设写这行就是 broken
手动 import 后    → resolve(...) -> <class IntentGuard>
                    registered_names() 从 9 个 → 10 个
```

⇒ `@register` 的全局注册表**技术上可用**，缺的是**自动发现**（目录扫描 / entry_point / JSON 声明注册各 **0**）。
而且即使加载成功，新能力若没有对应的内核消费点，生效消费点仍是 **0**。`KINDS` 在 `caps.py` 里只被引用 1 次（定义处），8 类其实 kind-agnostic —— **真正的天花板是消费点数量，不是 SPI 种类数**。

## 4. 现在到底能吸收什么（这是问题的核心）

| 别的 agent 的长处 | 通道 | 零改内核？ | 证据 |
|---|---|---|---|
| 一段纪律 / persona / 方法论文本 | 外部能力 `SECTION_TEXTS` + 预设点名 | ✅ **本轮打通** | 真 HTTP 14/0，`caps_ext_test` 36/0 |
| 一个工具 | `kind="tool"` 能力在 `mount()` 里 `ctx["registry"].register(Tool(...))`，并按约定写 `ctx["registered_tools"]` | ✅ **通道本就存在，本轮补了实证判据** | `caps_builtin.py:195-250`、`caps_ext_test` ②b 三条 |
| 图型 / 图注模板 | 老 `plugins.py` | ✅ 已有 | `plugins.py:105-122` |
| 开关 / 调已有判据的阈值 | 预设 `measured_metrics` 等 config | ✅ 已有 | `gate.py:459` |
| **一条新判据** | `_EXTRA_RULES` 7 条硬编码表 | ❌ 要改内核 | `gate.py:94-102` |
| **一个新工序 + 专属 skill** | 27 条 `Stage` 表 + `∈ STAGE_BY_ID` 校验 | ❌ 要改内核 | `stages.py:136-320`、`preset.py:154-156` |
| **换掉 system 骨架** | `complete:true` 结构性覆盖未接线 | ❌ 要改内核 | `caps_builtin.py:276-281`（`provides` 已写「[未接线]」，不假装生效） |
| **按任务裁剪 / token 预算 / 路由** | 无 SPI，`SYSTEM` 每场全量注入 | ❌ 要改内核 | `loop.py:51-185`，P4 |

**判断**：能吸收「**内容**」（文本、工具），还吸收不了「**规则**」（判据、工序、装配）。
原因不是插件协议不够，而是内核按 **8 个写死的行 id** 取值。要让「加行为 = 加插件」普遍成立，得把取值方式从「按固定 id 问」改成「按 slot 遍历所有已挂载能力」。

## 7. 边界与不粉饰

- **外部能力是进程级一次加载**：改 `.py` 后要重启控制台才生效，没有热加载。
- **坏件影响面被刻意放大**：一个外部 `.py` 导入失败，会让**所有预设**的 `healthy=False`（每份挂载都注入那条 external broken）。这是「坏件不静默」的代价，不是 bug；但部署时要知道。
- **只扫 `*.py`**，跳过 `_` 开头；不做签名校验、不沙箱。外部能力是**可信代码**，等同于往仓库里加模块。
- **`reset_external_loader()` 只撤能力名，不撤已注册工具**；工具生命周期仍由 `Rongke.run()` 的 `finally` 按 `Caps.registered_tools` 管（上一轮修的泄漏路径）。
- **本轮没有改 `index.html`、没有动 baseline 9 行值、没有 `--save`**（权威基线活路径仍缺失）。
- **上一轮 `regress_final6.log` 未收尾**：0 字节、进程已不在（会话切换时后台任务被终止），已跑到 23:19 的 `setup/analysis`。**不把它当绿灯报**。本轮重启了 `regress_final7.log`。
- 本轮解决的是「**能不能加载**」与「**能不能注入内容**」，**没有**证明外部能力让产出质量更好 —— 与上一轮「挂上了 ≠ 质量更好」同一条纪律。
