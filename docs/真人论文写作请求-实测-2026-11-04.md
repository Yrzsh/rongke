## 4. 实际暴露的问题（按伤害排序，都带证据）

### P1-a　两套 id，外部取产物会扑空
`POST /api/run` 回的是运行 uuid（`9ae5a3ded493`），而产物落在 `runs/20261104-125413`。按 uuid 调 `/api/artifacts?id=9ae5a3ded493` ⇒ `{"exists": false, "files": []}`；换成归档 id 才拿到 3 个文件。`/api/runs` 历史列表用的是归档 id，所以**界面上看得见产物**（已验证）；但 `/api/follow` 反过来只认运行 uuid。三个入口三种 id 语义，二次开发/外部复核脚本第一次必踩。
> 最小修法：`POST /api/run` 回包里带上 `archive_id` 与 `workspace`，或让 `/api/artifacts` 同时接受运行 uuid。

### P1-b　追问轮次的新指令没有进验收标准
C 的 `contract.acceptance` 与 A **一字不差**（仍是原来 5 条）。用户新加的三条——「末段压成两三句」「别加具体数」「贴全文」——**一条都没有判据覆盖**，门一次 `passed=true` 直接放。
独立复核显示产物碰巧全做到了（末段 1404→1318 字符、`new_nums_in_C = []`、`final` 含全文），但**这是模型自觉，不是门在管**。正是那句「判据的覆盖面 = 产出的上限」＋「这件事没做时谁负责说出口」。
> 最小修法：`/api/follow` 把本轮 `text` 里的约束并入/追加验收条款，至少让「不许新增数值」变成可核项（本轮已有 `read_file` 读回，成本极低）。

### P1-c　写作体检认不出〔n〕式引注
A 正文实有 **13 处〔1〕–〔4〕**、文献表 4 条，而 `lint.metrics` 是 `cite_numbers=0 / has_refs=0 / refs_n=0 / cite_first_order=[]`。⇒ 引注首现序、正文↔文献表一一对应这两条程序化判据**根本没跑**；这次靠模型自己写对，门没验。评测集 `w2-long-mixed-cite` 正是测这条，属实是真空地带。
> 判据形状：中文科技期刊常用的〔n〕全角括号不在正则里 —— 这是「判据在正确的稿子上不生效」，不是稿子的问题。

### P2-a　字数口径在追问轮次自相矛盾
C 把「正文＋参考文献表」一起塞进 `draft_text`（2116 字符），体检按含表 1239 字判「+24%、88 分」，而它自己在 `fix` 里写着「剔除后正文 992 字」。**算得出、却没用于判分**。A 只交正文（1037 字 / +8% / 96 分）。
按现行阈值（`硬问题>0 或 软建议>=4 或 分<70`），C 是 `hard=0 / soft=3 / 88 分` ⇒ **放行是规则内行为，不是门失守**；但用户一旦按「贴全文」下指令就会无谓掉 8 分。

### P2-b　成本：1.16M 输入 token 换 1037 字
A 22 步 × 每步约 5 万字符上下文 = 1,164,340 输入 token / 246 秒；同样写一段正文，B 只用 211,904 / 80 秒。缓存命中都在 93–96%，`pricing.models=[]` 导致 `cost_display=UNKNOWN` —— **跑完也算不出这轮多少钱**。
另：字数靠模型在 thinking 里估算（「正文约 1300 字符…让我数一下」），A 写了 3 次 `write_file`、B 写了 2 次，本质是「写→体检→再写」的反馈循环，没有便宜的字数工具。

### P2-c　恒亮警告 / 自述数字不准 / 中文 DOI 盲区
- 「交付物描述与证据措辞没有交集」在 A、B、C 每次交付**全亮**（11-03 记录是 35 次里 23 次）。恒亮的警告会训练用户无视警告。
- A 的 `final` 交付说明自称「约 1100 字，7 段」，程序化实测 **1037 字 / 8 段**。再次印证「自称成功永不算证据」。
- 2 条中文期刊 DOI 被 `verify_citation` 判「Crossref 查无此号」而弃用。模型已在文献表里注明成因（说明它知道这是盲区），但**工具层没修**：Crossref 落空回落到 doi.org / chndoi.org 这条 09-22 就写清、至今未落。诚实弃用不算错，代价是丢了两篇可用文献。

### 给评测集的一条提醒（不是荣珂写稿的错）
机械的 `numeric_anchor` 在 B 上会误报：正文里唯一「不在材料」的数字是 **5 株**（3 株候选＋2 亲本的派生计数）；而 `缺失值清单.md` 里还有 21、100、603 等**说明性示例数字**。若判据把清单并入正文分母，或把派生计数当测量值，一份完全合规的稿会被判红。⇒ **先问分母是什么、在正确的稿子上会不会报错**。

## 5. 建议（按性价比，都不需要换模型）

1. `/api/run` 回包带 `archive_id` / `workspace`，统一三处 id 语义（成本最低、外部最先撞到）。
2. `/api/follow` 把本轮新约束并入验收标准，尤其「不许新增数值」。
3. `lint` 的引注正则补〔n〕，并把「正文引注 ↔ 文献表一一对应」接进写作门。
4. 字数判据统一用 `chars_excl_refs`（它已经算出来了），别让「贴全文」触发扣分。
5. 恒亮警告改成给得出修法的一句话，或只在写作任务亮。
6. `verify_citation` 补中文 DOI 回落解析，并区分「未收录」与「不存在」。
7. 填 pricing 表 —— 否则任何成本结论都停在 `UNKNOWN`。
