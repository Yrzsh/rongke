# 荣珂订阅与授权方案 v2（2026-11-06）

> 触发：0.1.8 完成「框架 Apache-2.0 开源 + 桌面软件专有」双轨发布，并把朋友版
> 安装包发给周晓乐之后，原有「价格表 + 激活码」两条线不再自洽。
> 本轮**只出方案，不改代码**；实施清单与验收判据见 §9 / §10。

---

## 0. 一句话结论

**把「卖 token 额度」废掉，改成「卖期限授权」；把 `billing` 降为成本账本，
把 `license` 升为唯一授权单源。** 并且如实改名：在离线激活码架构下我们做的是
**期限授权（term license）+ 人工续期**，不是「自动续费订阅」——除非另做联网许可服务。

### 本方案采用的四条假设（一句话就能推翻，不阻塞执行）

1. 默认 **BYOK（用户自带模型 API key）**：token 的钱由用户直付模型厂商，站方不代收、不垫付。
2. 桌面版卖的是**省事**（安装即用、中文界面、原生出图、预设开箱、持续更新），不是软件副本——框架已开源，副本没有稀缺性。
3. 首轮以**个人年费**为主，不做自动扣款、不做中途退款、不做多用户账号体系。
4. 收款复用你已有的境内个人支付通道经验（虎皮椒 / XorPay），不新开经营主体；资质与发票边界按现状如实披露。

## 1. 现状诊断：五条结构性问题（都有落点，不是观感）

| # | 问题 | 证据 | 后果 |
|---|---|---|---|
| 1 | **两套真相，互不联动** | `billing.py:72` 的 `PLANS`（free/pro/lab/enterprise）与 `license.py:399` 的 `state()` 各判各的。激活码 `payload.plan` 只是个字符串（`tools/issue_code.py:98`），从不写进 `Account.plan`；账户默认是 `free`（`billing.py:472`） | 买「实验室版」的人，激活成功，控制台账单页仍显示「免费套餐 / $2 额度」。用户会认为付了钱没生效 |
| 2 | **收费口径自相矛盾** | `docs/产品说明.md:73` 按月费卖「模型成本额度」（$29 买 $30 额度）；`license.py:5-12` 的模块说明却明写「激活码里没有 token 额度，有的话就等于替厂商收钱」 | 一边说不代收，一边把代收做成套餐表。而 `pricing.py:25` 的**价格表默认是空的** ⇒ 所有成本是 `UNKNOWN` ⇒ 所谓「额度」连自己都算不出来，却拿它定价 |
| 3 | **没有收款，也没有订单** | `billing.py:898` `payment_connected=False`；`top_up()`（`billing.py:677`）docstring 明写「只写本地流水，不会真的收款」「接支付时必须替换整个函数」；`change_plan()` 不校验付款 | 现在所有「套餐 / 月费 / 余额」都是界面装饰。真收款链路一条都没通 |
| 4 | **订阅概念与离线授权根本冲突** | `license.py:97` `expires` 是**绝对 unix 时间**，`issue_code.py:97` 从**签发时刻**起算；码发出后纯本地校验、没有任何撤销通道 | ① 客户买了年费、拖两周才装，白少两周；② **停订 / 拒付 / 退款无法让已发出的码失效**；③ 「自动续费」在离线架构下不可能实现 |
| 5 | **开源双轨后，二进制不再是收费护城河** | `NOTICE.md` / `LICENSE`：框架 Apache-2.0，可商用、可修改；`license.py:34` 自己承认「不防懂 Python 的人删掉校验那一行」 | 若按「软件副本」定高价，理性用户直接 `pip install rongke-0.1.8-py3-none-any.whl` 自建。价格上限被开源版压死 |

**外加一个今天新出现的真实敞口**：`dist/RongkeSetup-0.1.8-Friend.exe` 内嵌你的明文
`CODEBUDDY_API_KEY`（`packaging/_friend_private/secrets.json`），已发给周晓乐。
这份包**没有到期、没有额度上限、没有回收机制**，等于一份无限期、由你付费的开放凭证。
它不能当订阅模板，必须单独收口（§7）。

## 2. 重构后的四条原则

| 原则 | 具体含义 | 它替掉什么 |
|---|---|---|
| **P1 授权单源** | 能不能用、用到哪天、几台机器、买了哪一档，**只由激活码说了算** | 替掉 `Account.plan` 与 `PLANS` 的「套餐」语义 |
| **P2 钱与额度分家** | token 账单 = 用户自己的**成本估算工具**（`UNKNOWN` 必须照实显示）；订阅费 = 软件使用权的对价。两者不出现在同一个界面概念里 | 替掉「$29 含 $30 额度」 |
| **P3 卖省事，不卖副本** | 定价锚点 = 安装/配置/更新的时间成本 + 持续维护，不是「一份软件多少钱」 | 替掉按软件副本估价的思路 |
| **P4 离线优先，诚实命名** | 保持不联网、不上报的卖点；因此对外说「年费授权 / 到期续期」，**不承诺自动续费、不承诺中途退款** | 替掉「订阅 / 月费 / 自动扣款」这些做不到的词 |

## 4. 授权凭证的新形状（唯一单源）

现有 payload：`{customer, plan, expires, issued, mid}`（`tools/issue_code.py:98`）。

新增加字段，**向后兼容**：老码（无新字段）继续验得过，按 `plan=pro / seats=1` 解释。

| 字段 | 类型 | 用途 | 校验方 |
|---|---|---|---|
| `plan` | enum | `personal_annual` / `personal_perpetual` / `lab` / `institution` / `gift` | 界面只读展示，不再另设 `Account.plan` |
| `seats` | int | 允许机器数；`mid` 仍是单值，`seats>1` 时由签发台账管多台 | 单码一机不变 |
| `starts_at` | float | **有效期起点**（下单/交付日） | 修掉「签发即起算、客户晚装白亏」 |
| `duration_days` | int | 期限长度；`0` = 永久 | `expires = starts_at + duration_days*86400` |
| `order_id` | str | 支付订单号，**幂等键** | 同一订单号只签一次码 |
| `channel` | enum | `paid` / `gift` / `internal` / `renewal` | 对账、区分赠送与付费 |
| `entitlements` | list | 资产范围（更新、模板、优先支持、私有部署） | 只作展示，不硬编码到门里 |
| `mid` | str | 一码一机（保留） | 不变 |

> **不要**把 token 额度、余额、`quota_usd` 写进凭证。`license.py` 的模块说明已经把
> 这条理由写透了，v2 只是让实现追上它。

| 换机 / 重装系统 | 客户发新机器码，人工重签一次，台账记 `rebind` | 人工 | 每人每年免费 1 次，第 2 次起按条款处理；旧码无法回收（如实告知） |
| 停订 | **不续费，到期自然失效** | `state()` 现有逻辑 | `now > expires` ⇒ `expired`，只拦发起新任务，历史与产出照常可读 |
| 退款 / 拒付 | 条款写明「年费授权一经交付不支持中途退款」；争议走人工补发/不再续期 | 条款 | 不在代码里假装能撤销已发出的码 |
| 对账 | `orders.jsonl` + `issued.jsonl` 双台账 | 新增 `tools/reconcile.py` | 每笔已收款订单恰好对应 1 张码；孤儿码（无订单）为 0 |
| 赠送 / 内测 | `channel=gift`，90 天，独立台账 | 签发工具 | 到期自动停；不与付费订单混账 |
| 开源用户回流 | 框架用户想要「装完即用 / 更新 / 支持」时转桌面版 | README | 两条路径说明互不贬低、互不混淆 |
| 升级 / 降级 | 补差价换新码，旧码不作废但台账标 `superseded` | 人工 | 不承诺回收，只承诺新权益生效 |
| 资质 / 发票 | 经营主体、发票、退款条款 | 你 | 文档如实写「个人收款，发票能力以实际主体为准」，**不编造** |

### 三条必须写进条款、不能靠代码解决的边界

1. **离线码发出去就收不回** ⇒ 不能承诺「随时停订即时失效」。要即时撤销，只能做联网许可（机构版），那会放弃「不联网、不上报」卖点。
2. **不防破解**（`license.py:34` 已自认）⇒ 目标是让诚实的人走正道，不是拦住铁了心的人。
3. **收款资质属于经营主体**，不属于软件功能；`docs/产品说明.md:108` 已有这句，v2 保留。

## 7. 成本隔离：BYOK 与朋友版收口（今天就要处理）

**默认付费版一律 BYOK**：安装包不含任何 API key；`config.json` / `secrets.json` 由用户自己填
（`packaging/INSTALL-NOTES.txt` 已有配置说明）。站方不承担 token 成本，这是 §3 定价成立的前提。

**已发给周晓乐的那份朋友版**，按优先级处理（三件事互不替代）：

| 顺序 | 动作 | 理由 |
|---|---|---|
| 1 | **把内嵌 key 换成一把独立的、限额的子 key**，不要再用你的生产 key | 现在这把 key 一旦外泄或跑飞，损失直接落在你身上，且无法只停某个使用者 |
| 2 | **补一张 90 天 Gift 激活码**（`channel=gift`，`duration_days=90`） | 让赠送有终点，到期自动停；同时把它和付费订单分开记账 |
| 3 | 给朋友一份「换成自己 key」的一页说明 | 长期看，让对方 BYOK 才是唯一没有持续成本敞口的形态 |

> 如果朋友就是要「装完即用、不配 key」：那就明确这是**你补贴的赠送**，在网关侧设
> 月额度上限并**定期轮换 key**；不要把它变成一条收费产品线——补贴成本会随人数线性增长，
> 而 ¥199 的年费覆盖不了重度 token 消耗。

## 8. 与开源双轨的关系（这是定价的天花板）

| | 框架（Apache-2.0） | 桌面软件（专有） |
|---|---|---|
| 能不能商用 | 能，可修改可再分发 | 需授权 |
| 谁在维护 | 社区 + 你 | 只有你 |
| 收费理由 | **不收费** | 省事、更新、资产、支持 |
| 绕过难度 | 本来就开放 | 懂 Python 的人可绕过（`license.py` 自认） |

**结论**：不要把「防止别人拿到软件」当商业模式。收费必须建立在**持续交付的价值**上——
更新、预设/模板/技能资产、中文界面与开箱即用、问题响应。这也意味着 v2 的一个硬要求：
**年费用户必须真的持续收到更新**，否则续费率没有支撑，方案退化成一次性买断。

## 10. 验收判据（实施时的硬门，全部要「读回」）

- **正负控**：同 `mid` 的码通过；换机器码的码被拒；改一个字符的码验签失败；`now=expires+1` 判 `expired`。
- **幂等**：同一 `order_id` 重投回调两次，签发台账恰好 1 行、产出恰好 1 张码。
- **起算点**：`starts_at` ≠ `issued` 时，`expires` 按 `starts_at + duration_days` 算，交付晚装不亏天数。
- **单源一致性**：激活年费码后，界面档位 / `/api/license` / `Account` 不再出现「免费套餐」；账单页 `UNKNOWN` 不被渲染成 `0`。
- **续期无空窗**：`--renew` 后新码 `expires == 旧 expires + 365 天`。
- **回归**：`regress.py` 全绿且 `REGRESS_EXIT=0`（只认日志尾的 `REGRESS_EXIT`，不认外层 exit code）；不并发跑测试、不带 `--save`。
- **发行件**：若动了 `workspace.js`，三件发行件重出、SHA256SUMS 重算、安装版冒烟重跑。
- **脱敏**：公开树扫本机绝对路径 / 明文 key / 订单台账文件名，命中数必须为 0。
