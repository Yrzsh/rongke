# 导师模式：组会预演 / 开题答辩（2026-11-14 续）

> 用户原话：「继续优化导师模式主要要解决的问题，例如，组会汇报前总会先找人评价
> 一下自己的汇报，又或者加深自己对课题的理解，因为开题需要你对自己的课题理解的
> 非常清楚，包括一些细枝末节，防止被答辩老师问住」。
>
> 这一轮只动导师模式，没碰写作流 / 出图 / 计费。

---

## 0 一句话结论

上一轮（`导师视角升级-2026-11-14.md`）把导师做成了**审稿席上的人**，判据是
「这份稿子站不站得住」。但用户这次点的两个场景**不是交稿前终审**：

| 场景 | 他要的东西 | 上一轮能给吗 |
|---|---|---|
| 组会汇报前找人看一遍 | 「我明天要讲，会被问到什么？」 | ❌ 只有「哪里写错了」 |
| 开题前加深理解 | 「我自己到底懂不懂，细枝末节扛不扛得住追问？」 | ❌ 只有「论证有没有洞」 |

所以本轮**加两个预演镜头**，并把这条链路上三个真缺陷修掉（它们全是在组会/开题
材料上暴露的，普通论文稿碰不到）。

---

## 1 三个真缺陷（先量到，再修）

探针 `_probe_rehearsal.py` 先在**真回包** `runs/_mentor_ab_out/A1.md` 与一份
组会大纲上量，三条全部复现，才动手改。改完同一条探针全绿（负控见 §4）。

### ① 「递了成篇材料」的判据里含换行 ⇒ 恒真

```python
has_artifact = any(len(d) >= 120 or "\n" in d or "|" in d for d in docs)
```

而 `loop.initial_messages()` 传进来的第一件 artifact **就是 goal 本身**
（`_artifacts = [_goal] + _brief["sources"]`）。于是 `"\n" in goal` 恒真：

| 输入 | 改前 | 改后 |
|---|---|---|
| `在吗\n问个问题` | **判成「有可评审对象」** | 不评审 |
| `帮我看一下这个\n怎么改比较好` | **同上** | 不评审 |

11-03 那个「你好 → 组会点名」的故障并没有被彻底关掉 —— 它只是从「你好」挪到了
「任何带换行的短句」上。**换行是排版，不是篇幅。**

**修法**：判据改成真字数（`_ARTIFACT_MIN_CHARS = 60`），或者**本身是一张表**
（≥2 个 `|` 的行）—— 表再短也是成篇东西。并新增 `sole_request` 信号：
「明确要评价但没递材料」时给一段**短的**立场段（说明要他递什么），
既不凭空开评审，也不至于把「帮我看看这段行不行」答成一句空话。

### ② `material_issues` 只认 CSV 当复算锚

组会讲稿、汇报大纲、开题报告里的「原表」几乎总是 **Markdown 表**。只认 `csv_text`
的后果不是「少报几条」，而是**空头支票**：立场段写着「内核已按原表/原文算出下面
这些疑点」，下面其实是空的 —— 模型会据此跳过真正的核数。

**修法**：`_md_table_cells()` 认 Markdown 表，逐列重算同一套描述统计白名单
（均值/极值/分段均值/差分/计数）。**口径单源**：`_allow_from_cols()` 被 CSV 与
Markdown 两条路共用，一份白名单不许有两个副本（H 型缺陷）。
表格行本身**不参与断言核验** —— 表里的数是定义，不是结论。

### ③ 预演回包解析不出来

模型自然写的是 `[Q1] …` 配「问题：/怎么答：」。原来只认 `[P1]` 与「怎么改：」，
于是一份正确的预演被判成 **0 条 finding + 七字段缺失**。

**修法**：`_RE_REHEARSAL_ITEM` 认 `[Q1]` / `【问1】` / `【追问1】` / `(Q1)`；
字段别名「问题 / 怎么答 / 拿不准」也认。`Finding` 新增 `question` 字段
（标号 ≠ 严重度，不许混进 `severity`，否则 R6「PASS 不许挂 P0/P1」会误判）。

### ④ 顺手修掉的两处「算过了但谁也看不见」

- **`case "mentor_review"` 全仓没有**。内核从上一轮起就 `tee("mentor_review", …)`
  推这条事件，前端从来没人收 —— 同一类失效在本仓已经发生过三次
  （`mentor_audit` 造了没 emit、`force_brief` 判据写了没人调）。
  现在有 `renderMentorReview()`，并把「追加到答复」这件事也显示出来。
- **读回不合格时，`next_action` 只进了 result 与事件**。一份 0 条问题、没挂位置、
  自称「多位评审一致认为」的预演会**原样交到明天就要上台的人手上**。
  现在 `review_audit` 不合格时，把补齐清单追加到 `result.final` 末尾
  （`audit_addendum()`），并记 `appended_to_final`。

## 2 本轮落地：两个预演镜头

`REHEARSAL_LENSES`（与 `LENSES` 并列，**不替代**）：

| key | 名字 | 它问的问题 |
|---|---|---|
| `group_meeting` | 组会预演：会被当面问住的地方 | 站在台下想挑你毛病的人的位置，他会先问哪三句？每句都要指到你的某一页/某一句。 |
| `defence` | 开题/答辩预演：有没有你真答不上来的 | 不评措辞、不评讲得好不好，只查「你到底懂不懂」：为什么是这个物种/方法/对照，参数怎么定的，与最接近的工作差在哪。**一路往下追问到答不出来为止，那一层才是产出。** |

触发是**行为判定**（`is_rehearsal_text`），词表刻意窄 —— 只收「马上要讲/要答辩」
那一刻的说法（组会、预讲、试讲、答辩、开题、被问住、模拟提问…），不收
「写了一篇论文」「汇报一下进展」这种普通任务（同 `_DECK_WORDS` 那次教训）。

### 判据：预演给 PASS 要打回去（R11 / R12）

| 判据 | 内容 |
|---|---|
| `R11_问题条目用 Q 标号而不是 P 档` | 以问句形式写出来的条目不许挂 `P0` 档 —— `[P0] 中段的 45% 是哪几批的均值？` 把「多严重」和「第几句追问」混成一档。判「是不是问题」看**句子本身**（问号 / 问句开头），不看 `question` 字段（那个字段在 `[P0]` 写法下天然为空，拿它当判据永远判绿）。 |
| `R12_预演必须真的给出会被问住的问题` | 预演的产物本来就是问题清单：给 PASS / 0 条，读的人会以为「没问题」，那他明天上台时才发现没有。**这条是承重的**，负控见 §4。 |

其余 R1–R10 一条没松：七字段、位置可定位、证据不许是猜测、不许冒充多评审。

## 3 判据改了就要重跑负控（本轮踩到两次）

- **R10 差点被自己的结论满足**：为了绕开「出口现算触发条件」，我第一版写成
  `bool(trigger["review"]) or bool(findings)` —— 那等于「写了 finding 就算合规」，
  对一句「你好」硬开一场评审也会变绿。**上面 §1① 修掉的正是这个问题的源头，
  判据里再开一次后门就等于白修**。改回「输入侧判定过要评 / 明确说了在预演」。
- **R11 第一版永远判绿**：判据写成 `(not f.is_question) or not f.severity`，
  而 `[P0]` 写法下 `is_question` 恒为 False ⇒ 恒真。负控立刻打红。
- **R12 顺手把 R11 的负控带红**：`[P0]` 条目不算「问答形态」⇒ 两条一起翻。
  定向负控要求「只翻自己那一条」，所以 R12 也改成认问句形态。

## 5 一处如实记录（不是缺陷，是设计）

**工作区里摆着一份成篇大纲时，说「你好」也会进评审视角**（终审口径，不是预演口径）。
这是上一轮「递东西过来就是要你看」的原意，本轮没有改。它和 11-03 那个故障的区别是：
那次是**空工作区 + 你好**被答成组会点名；现在空工作区 + 你好 一个字都不注入
（有负控）。如果用户觉得「桌面上摆着别的文件时问一句你好也被评审」很烦，
要改的是 `mentor_brief` 挑文件的口径，不是触发判据。
