# 开题大纲：从「输入课题信息」到「论文每一节填什么数据」

**2026-11-15** · 荣珂 · 18 次真实模型运行里抓出来的四件事

---

## 一、这个功能要解决的是哪个洞

课题台账（`topic.py`）里早就有 `PLAN.md`。它有字数、有章节、甚至能写技术路线。
但它**没有任何一处强制回答一个问题：这句话靠哪个数据成立。**

于是真实使用里长出来的是三份互不相干的散文：

| 在哪 | 它说什么 |
|---|---|
| `PLAN.md` | 我打算做融合、做鉴定、做稳定性 |
| 实验台账 `LAB.jsonl` | 我做了 19 件事（其中大部分是定性观察） |
| 论文/开题正文 | 第 5 章「融合子的多证据鉴定」 |

三者**永远对不上，而且没有任何东西会报错** —— 直到答辩被问「这一段的数据在哪」。
用户的原话是「开题需要你对自己的课题理解的非常清楚，包括一些细枝末节，防止被答辩老师问住」，
而细枝末节恰恰是散文结构装不住的那一层。

所以功能不是「再写一份大纲」，是**让「要写什么」和「要做什么」之间必须有一条连线**：

```
章节 ──needs（要什么数据）──> 由哪个实验供应（feeds）
```

## 二、落地形态

- `rongke/outline.py` —— 新模块。`topics/<slug>/outline.json`（机器对账用）+ `OUTLINE.md`（人看，**由 json 渲染，别手改**）。
- 三只手套：`outline_save`（敲定） / `outline_status`（对账） / `outline_to_lab`（把缺的数据排成实验）。
- `outline_test.py` —— 65 条判据，每条核心断言都配负控。
- 工具总数 86 → 89；课题工具 13 → 16（三处口径同步改：`mentor_workspace_test`、`docs/产品说明.md`、`--tools`）。

### 四条设计纪律（都来自真实失败）

1. **数据需求必须指到章节，实验必须指到数据需求。** 孤儿实验 = 做了不知写进哪；孤儿需求 = 这一节写不出来。
2. **`status` 是声明，不是事实。** 实验到底做没做，事实在实验台账里。`have` 一律去台账核，核不上降为 `unverified`。
3. **不留孤儿数据。** 删一节，挂在它下面的数据需求保留并标 `orphan=True`，不跟着消失。
4. **不做模板填空题。** 四类章节骨架只用来查漏（有没有整类缺失），不用来自动填充。

## 三、真实运行抓到的四个缺陷（这是本文档存在的主要理由）

65 条判据全绿的时候，功能**一次都没被真正用起来**。以下四条都是跑真实模型、真实 HTTP、真实界面抓出来的。

### 缺陷 1：提示词把模型指向了 `write_file`，不是 `outline_save`

**证据**（`runs/20261115-213521`，`conversation.done.json` 第 24 条消息）：

> 材料已核验完毕。现在先按技能要求冻结大纲并保存到磁盘，再回答。
> `[seq=15 write_file ok 11ms]` ✔ 已新建：outline.md

模型**明确说了**它要「冻结大纲并保存」，然后用了 `write_file`。
根因在 `rongke/stages.py:412`：

```python
"  ① 先冻结大纲：落盘 `outline.md`，每章写清——一句话论证 / ..."
```

这行是 2026-10-22 写的，那时 `outline_save` 还不存在。而在同一份提示词里，
`advisor_save` / `read（落盘用 `advisor_save`，读回用 `advisor_read`）` 是写了工具名的 ——
**导师模型那段会跑，这一段不会。差别就在这。**

**修法**：把指令改成工具名（`stages.py:408-430`），并显式写「不要用 `write_file` 写自己的 `outline.md`」。

**教训**：工具说明再详细也没用 —— **模型走的是提示词指向的地方**。
新增一只手套时，必须回头搜一遍提示词里有没有旧的手工做法在抢它的活。

### 缺陷 2：出口的评审尾巴，把「建大纲」当成了「评审」

**证据**（`runs/20261115-203402`）：用户说「帮我把大纲定下来」，回包末尾却附着

> ═══ 导师视角读回：这一份现在还交不出去 ═══
> 缺的是：R1_有结构化 finding / R6_判定与严重度一致 / R7_至少覆盖两个审查镜头 / R9_…

三层原因，**每一层都单独够修一次**：

1. `_artifact_like()` 只判长度 ≥120 字。用户一句话交代课题就有 65 字 → 被当「递了成篇材料」。
   而且判据用的是 `[goal]` 自比 —— 用户的请求永远算「材料」。
2. `_RE_REHEARSAL` 里有裸的 `开题`。「明年开题」是**时间点**，不是**要上台**。
3. 出口 `_want = ... or _mb["n_files"]`：「本轮落盘了材料」被当成「要评审」，
   而建任何产物都会落盘材料 —— **任何产出任务都会触发**。

**修法**（三层都改，各配正负控）：

- `_artifact_like` 改「够长 **且** 多行」。真实稿子是多行的；一句话需求是一行。
- `开题` 收窄为「开题 + 答辩/预演/被问/快到了…」或「开题答辩」「开题在即」。
- 出口改为 `signals.asks and review` 或 `is_rehearsal_text` —— **用户明确要评价才算**。

**验证**（`runs/20261115-213521`）：`导师视角读回` 不再出现在 final 中；
同时「帮我把这份讲稿评一评」仍然触发（不是把这功能砍掉了）。

**教训**：**「有没有产生文件」不能当作「用户要不要评审」。**
立场段要由**返回类型与请求**决定，不能由旁证决定。

### 缺陷 3 ★：一条数据需求都没写的节，对账给绿灯

**证据**（`runs/20261115-214318`，真实产出）：33 节里 8 节 `needs` 为空
（全部引言 + 结论），`reconcile` 返回 **`ok: True`**。

因为 `ok` 只算了三类：`starved`（要了数据没人供）/ `orphan_experiments` / `unverified`。
**「根本没要」这一类不在里面。** 于是一份有八节空白的大纲拿到了绿灯 ——
而这正是本模块存在的理由。

引言确实不需要实验数据，但它**必须声明它靠什么成立**（引哪几篇文献）。
一条不写 = 这一节现在写不出来。

**修法**：新增 `empty_sections`，并入 `ok`。负控：补上一条需求后必须转绿。

**教训**：「三类缺口」这种列表永远可能漏第四类。
对账函数要问的不是「我列的都检查了吗」，而是**「什么样的一份东西能从我这里拿绿灯」**，
然后拿一份真实产物去喂它。

### 缺陷 4：`path_of()` 给不存在的课题返回一个看着正常的路径

判据 `不存在的课题 ⇒ 路径 None` 一开始是红的。`_d()` 只验证形式（合法 slug、不越界），
所以一个**从未建过**的课题也会得到一个路径；调用方拿它 `write_text` 就会凭空造出目录，
而回包看起来像「已保存」。

**修法**：`path_of` 里加一道 `read_topic(slug) is not None`。
**教训**：「路径能算出来」与「目标能写」是两件事。

## 四、怎么复现这一整套

```powershell
# 1) 判据
python outline_test.py              # 65 项，核心断言都配负控

# 2) 真实跑（这才是抓到上面四条的地方）
python -m rongke --web --port 61245
#    POST /api/topic  {action:"use", slug, title, question}
#    POST /api/run    {goal, kb_only:true, mode:"answer", topic:slug, max_steps:18}
#    GET  /api/run?id=...   （事件类型是 tool）

# 3) 看结果
python -c "from rongke import outline as O; print(O.reconcile('cordyceps-protoplast-fusion'))"
```

**验收口径**：`runs/20261115-215522`（一次干净完整的使用）
—— 8 章 / 29 条数据需求 / 15 个实验，`starved=0 orphan=0 unverified=0 empty=0`，
29 条需求**全部**有实验供应，`have_metrics` 为空（台账里确实一条测量都没有，没造假）。

## 五、还没做的

- **50 字以上的手改会被覆盖**：`OUTLINE.md` 是渲染产物，手改下次 `save` 就没了。文件头写明了，但没有编辑入口。
- **`depends_on` 只校验存在性，不查环**。两实验互为前置目前不会被拦。
- **指标名匹配是宽松包含**（`转化率` 能匹配 `融合率%` 之外的都不会匹配，但 `率` 这种短词可能误中）。
  对账只把状态标为 `done`，不改用户原话，所以最坏情形是假绿 —— 已记在此处，未加重。
- **`outline_to_lab` 只造 `todo`，不造 `measure`**（红线）。真实跑里模型没有调用它，因为它选择直接交付大纲。
