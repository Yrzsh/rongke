# 荣珂 · 导师模式真实卡点实测报告

日期：2026-11-03
方法：**不问一句话、不预设问题**，直接向内核 `Rongke(cfg).run(q, kb_only=True, mode="mentor")` 发 22 个真实问题
（A/C/E 组开导师模式，B/D 组同一问题关导师模式做对照），全程记录思考链、工具调用、门判决与最终答复。
运行环境：`deepseek-v4.1-flash`，课题 `cordyceps-protoplast-fusion`（中国被毛孢 × 蝙蝠蛾拟青霉原生质体融合）。

原始数据：`_rk1_probe/_rk1_out/*.json`（逐轮事件流）与 `_rk1_probe/*.log`（可读轨迹）。

## 一、先给结论

导师模式的**内容质量已经在可用线以上**：22 个真实问题里没有一次"答非所问"，
参数带 doc_id + 页码、冲突如实并列、"库里没有"会说没有。真正卡住学生的不是它答得不对，
而是**四类工程性卡点**，按伤害排序：

| 级别 | 卡点 | 一句话证据 |
|---|---|---|
| P0 | 写稿任务的最终答复是**空**的 | 开题报告跑 38 步、落盘 10271 字，`final` = `""` |
| P1 | 方法资产被**套用到不属于它的课题**上 | 打招呼「你好」→ 输出一整套 DAPI 染色方案 |
| P1 | 工具回包被**按 6000 字符硬切**，模型被迫重查 | 回包总字符的 46% 被裁（59.9 万 / 70.2 万） |
| P1 | `kb_search` 多词查询近乎不可用 | `"菌丝生长速率 菌落直径"`（库里有据）→ `n: 0` |
| P2 | 中断/失败时用户拿到的是**空白** | 网络一抖，已跑 9 步的成图任务最终答复为空 |
| **P0** | **模型每次检索只看得见前 800 字** | 10 条命中，它只认识其中 2 条的编号（见第十节） |

> 第 4 条最初被我写成"切法让证据门判错"，**实测不成立**：证据门取的是全量 result，
> `_covers()` 负控 7/7 全对。切法伤的是模型（看残句、重复查），不是门。已改正。

## 二、P0：写作任务的最终答复为空

**现象**（`a05` / `b05`，同一问题，开关导师模式都一样）：

```
Q: 帮我写一篇开题报告，题目是虫草菌原生质体融合育种。
steps=38  耗时 688s  success=True  证据门通过
workspace/虫草菌原生质体融合育种_开题报告_final.md = 10271 字 / 89 段
result.final = ""
```

聊天窗口里学生看到的是**空白**。文件在磁盘上，但导师模式的主界面是对话（`mode=chat`），
学生不会去工作区翻文件。

**影响面**：不只是 a05/b05。C/D 两组里凡是要求"写点什么"的（`e07` 摘要）也是同一种形态 ——
`摘要.md` 339 字写好了，`final` 是一句 78 字的概述，正文不在答复里。

**不成立的解释**：不是模型偷懒 —— 思考链显示它连续两次为"字数 430→393→339"自我修正，
最后一步的 `content` 明确是"我再稍压一点…然后交稿"。是**交付通道**把正文吃了。

**建议**：`answer_only` / `mode=chat` 且交付物是单文件正文时，`deliver_task` 应把文件全文
（或前 N 字 + "已落盘"）回填进 `final`。判据：对 a05 重跑，`len(result.final) > 3000`。

## 三、P1-a：「你好」被答成了 DAPI 染色方案

**现象**（`e06`，导师模式，输入就两个字「你好」）：

```
TOOL 1 lab_method {"need": "staining", "slug": "cordyceps-protoplast-fusion"}
FINAL: 核质染色方法卡已按库内两套已发表方案渲染出来（DAPI 5 μg/mL…）
```

思考链里的原话：

> "用户只是打招呼。按契约：直接回答，不找证据… 不过我可以提到库里的冲突吗"
> → 然后它调了 `lab_method(need="staining")`

**根因**：`mentor_mode_text()` / `MENTOR_METHOD_TEXT` 把「成套方法先调 `lab_method`」
写成了铁律，但**没有任何一句说"打招呼/寒暄不要调工具"**。这段提示词只在导师模式下注入，
所以非导师模式（b 组）的同一问题不会出现。这是提示词缺口，不是模型抽风。

**代价**：学生说「你好」，拿回一屏 DAPI 浓度梯度。第一次用的人会以为这东西坏了。

**建议**：在 `mentor_mode_text()` 的「关于实验进展与数据」之前加一条：
> 我只是打招呼、道谢、确认在不在时，**不要调任何工具**，用一两句回，再问一句今天要推进哪件。

判据：对「你好」重跑，`tool_spans == 0`。

## 四、P1-b：工具回包按 6000 字硬切，模型是在残句上做判断

**实测数据**（实际落到盘上的 19 次运行的全部工具回包）：

```
回包总字符 701,766   被裁掉 598,914   占 46%
```

`config.py:55` 的 `max_observation_chars = 6000` 是**单一上限**，对 `kb_list`（12024 字符）、
`topic_status`（12024+）、`kb_bibtex`（最长 30874）一律拦腰切。这不是"少看点"，
它产生两个连锁伤害：

### 伤害 1：模型被迫重查，白烧 token

`a01` 与 `b01` 是同一问题。a01 多查了一次库：

```
a01: kb_search("菌丝生长速率 菌落直径") → {"ok": true, "n": 0, "hits": []}
```

零命中 → 它转头再去调 `lab_method(identity)`，**多跑 1 步、输入 token 从 28741 涨到 46767**
（a01 30.9s vs b01 15.2s）。真正的原因是这句话本身没进检索（见第五节），
但"查一次就白"的成本会叠加在每一次对话上。

### 伤害 2：回包被切开，模型看到的是残句

`b05` 里 `topic_status` 的模型可见长度 12024，被丢掉 17349（**59%**）；
`kb_bibtex` 丢 18850（**61%**）。模型据此下判断，等于拿半张表做决策。

> 更正：这一条我最初判成"让证据门判错"。**不成立** —— `mentor_trace_audit` 取的是
> 全量 result 不是预览，而 `gate._covers()` 的负控探针 7/7 全对
> （见 `_rk1_probe/_rk1_covers_probe.py`：`kb_read(kb478857a9 p.2-3)` 等 5 种写法都被正确接受，
> `kb_search` vs `kb_read` 被正确拒绝）。切法伤的是模型，不是门。

### 建议

1. `max_observation_chars` 按工具分化：台账/清单类（`topic_status`/`kb_list`/`lab_report`）
   给分页参数而不是硬切；`kb_*` 保持 6000 但**在正文里明确告诉模型"被切成两半，需要后半段请传 page/offset"**。
2. 截断提示语目前是 `…（已截断，原始 N 字符）`，**没说怎么拿回来** —— 这是可执行性缺口。

判据：同一问题重跑，`result_dropped / (result_chars + result_dropped) < 15%`。

## 五、P1-c：「导师查库查不到」这件事是真的

`a01` 的 `kb_search("菌丝生长速率 菌落直径")` 返回 `n: 0`，而这句话在库里**确实有** ——
`lab_assets.py` 的 quant 方法卡就锚在 `kb1611da3e p.3`（菌落半径法、每 24 h 量十字直径）。
`b04` 里 `kb_search("protoplast regeneration frequency mannitol")` 也返回 0。
`e07` 的思考链更直接：

> "多词组合的中文查询在这个库里会返回空结果，与 PLAN.md 中的记录一致；改用单个检索词。"

模型自己学会了绕，但**新用户不会**，他会以为自己的文献没入库。
导师模式的提示词里已经有一段"拆成文献里会出现的术语、一次两三个"，方向是对的，
但 `kb_search` 工具本身对多词查询近乎不可用。这是检索侧的真缺陷，不是提示词能补的。

判据：对上述三条查询分别返回 `n > 0`，且 `kb1611da3e` 命中。

## 六、P2-a：失败/中断时答复是空白，磁盘上是半成品

`c05` → `d05`/`e05` 同一问题「帮我把这个课题的实验数据画一张图」：

| 运行 | 结果 | workspace |
|---|---|---|
| c05 | 第 9 步 LLMError（DNS 抖动） | `data/progress_matrix.csv`、`data/ledger_matrix.csv` —— **半成品，没有任何说明** |
| e05 | 成功 | 20 个文件，`audit_figure` PASS |

学生断开后重进 `c05`，看到的是两个 CSV 和一个空对话框。**这恰恰是荣珂当初要消灭的形态**
（"7 个中断任务没有归档"）。中断快照 `conversation.json` 在，但没有任何一句人话告诉学生
"这次断在第 9 步，已经跑到哪、产物是半成品，点这里续跑"。

**建议**：`crash` 分支必须写一句进 `final`：中断在第几步 / 已经产出了什么 / 哪些是半成品。
判据：构造一次中断，`len(result.final) > 0` 且包含已产出文件名。

## 七、P2-b：几乎每轮都亮的那条警告，等于没有信息

`a06`（导师模式）与 `b06`（非导师模式）同一问题，两者都对，但 a06 用了 8 次工具、46.5s，
其中 `topic_status` **调了两次一模一样的参数**（seq 6、7），`load_skill` 两次。

两者的证据门警告都是同一条：

> `交付物描述与证据措辞没有交集（不影响判定，仅供自查）`

这条警告在**全部 35 次运行里出现了 23 次**（含 8 次网络中断的无交付运行）——
**三分之二的运行都会亮**。

（顺带说明：我一度怀疑 `_covers()` 会误伤，写了负控探针验证，7/7 全对，
`kb_search` vs `kb_read` 也正确拒绝。那条怀疑是**错的**，已撤回。见 `_rk1_probe/_rk1_covers_probe.py`。）

**建议**：要么给出可执行的修法（"把 deliver_task 的 summary 改成以产物名开头"），
要么只在写作任务上亮。恒亮的警告会训练用户无视全部警告。

## 八、内容层面：对得上的地方（也是判断基线）

不全是问题，下面这些实测是**对的**，改代码时别弄坏：

- **参数只从文献取、冲突并列**：a03/e08 明确写出"两篇 DAPI 差 1000 倍（5 μg/mL vs 5 mg/mL），落点只能自己量"。
- **会推翻学生的前提**：c04 抓出学生给的 `2.74×10⁻³` 与库内原文 `2.74×10⁻⁵` **差两个数量级**，
  并说"先核对分母和上标，别在可能抄错的数上改配方"。这是真导师行为。
- **区分"文献有"与"我的判断"**：a04 明确标了「我的判断（不是文献结论）：5% 可能是酶解过彻底」。
- **空库不装懂**：e07 思考链里主动放弃了"已有研究表明"这类无出处句式。

### 一个词表层面的隐患（未致错，但会错）

`lab_assets.IDENTITY_CHAIN` 是**写死的四环**（核相→拮抗→酯酶→ISSR），锚点固定为
`kb1611da3e` / `kb2466e972` / `kb4452729c`。本次库里 `kb4452729c` **查不到**
（35 次运行的回包里只在 `b05` 命中过 `kb1611da3e`，`kb4452729c` 一次都没有）。
现在模型会同时调 `lab_method(identity)` 和 `kb_search`，所以没出错；
但一旦它只信 `lab_method`，就会把一个**不属于任何具体课题**的资产当成"这个课题的证据链"。
建议：`IDENTITY_CHAIN` 的每个环在返回时都标注"本条来自方法资产库，不是本课题文献"，
并让它去 `kb_search` 各环关键词确认是否命中。

# 第二轮：换成真实处境的问法（2026-11-03 下午）

第一轮问的是"技术问题"，回答都不错。第二轮换成**研究生在真实处境里会问的那种话** ——
带截止日期、带导师压力、带"万一这是个假问题"的恐惧。这一组一共 5 个问题，
问出了第一轮没暴露的东西，也**推翻了我第一轮的一处判断**。

## 十、最关键的发现：模型每次检索只看得见前 800 字

`u04`（"这两个名字是不是同一个种"）第 4 次检索：

| 项 | 数值 |
|---|---|
| 完整回包 | **9924 字符**，10 条命中 |
| 模型实际看到 | **800 字符**，2 条命中的 doc_id/page |
| 预览可否解析 | **否** —— JSON 在第一条 snippet 中间就被切断 |

也就是说，它一次检索拿到 10 篇，只认识其中 2 篇的编号；剩下 8 篇的**标题和摘要都读不到**。
提示词里还在教它"先看 snippet 对不对题"，可 **snippet 根本没送到它面前**。

这条比第一轮"46% 被裁"严重得多：第一轮我量的是 `result_chars`（6000 上限），
那是**上下文窗口**的口径；而**模型真正看到的**是 `result_preview`（800 字）+ anchors。
两个口径不一样，第一轮把它们混在一起说了，这里更正。

### 它是怎么"看着有"的

我把 25 处引注逐条对着"模型当时看得见的证据"核了一遍：

```
合计 25 处：可直接核对 0，被截断遮蔽 14，本次没检索到 11
```

那 11 处，我又去 `litkb/library.json` 逐条点名（252 个 id）：

```
kb60993237 / kb60690152 / kb1632d076 / kb8324a958 / kb5574c7da
kb9590e167 / kb478857a9 / kb59552557 / kb1611da3e  —— 全部「库里在」
负控 kb12345678（我编的）—— 「库里不在」
```

**结论：没有一处编造。** 引注全部来自库里真有的文献，只是它们是从
**上下文的历史命中、方法卡、系统提示**里取的，不是这一次检索跑出来的。

对**导师场景**（答疑、判断、给建议）这没问题 —— 一个记得住自己库的导师是好导师。
但它有两个后果，都该改：

1. **写稿场景是致命的**。开题报告、综述、返修信要的是"本文引用的每一篇都读过原文"，
   而现在模型对 8/10 的命中只见过编号。文献表里的页码有一半它没从这一次检索里拿到。
2. **新进库的文献它永远看不见**。命中排在后面的那 8 篇里要是有刚入库的关键文献，
   模型连着几轮都不知道它存在 —— 而提示词还在告诉它"库里没有就明说没有"。

### 建议（按优先级）

1. `result_preview` 的结构要保住：**先给全部 n 条的 `doc_id + page + title`，
   再给前几条 snippet**。现在是把整个 JSON 从头切，切的正好是"有哪些篇"这段索引。
   这条改完，8 篇被丢掉的命中立刻回到模型视野内。
2. 截断时补一句"这是 10 条里的前 2 条，要第 3 条起用 `kb_read(doc_id, page_from)`"。
3. 写稿/成文类任务（`needs_writing=True`）应该**强制**把每一处〔库·doc p.N〕先过一遍
   `kb_read`，判据是"引注页 ⊆ 本次 kb_read 覆盖页"，而不是"⊆ 本次检索命中页"。

判据：对 `kb_search(Paecilomyces hepiali 鉴定 分类)` 单测，
模型可见预览里应能数出 10 个 doc_id。

## 十一、中间动作在哪里被机械台账压掉

`s01`（带期限、带导师压力的"我该先做什么"）的思考链里有这么一段：

> "**染色条件是方法学摸索，失败率高、周期长、且目前连融合子都还没有**"
> → "但让我想想哪个真的更优先……"
> → 最终选了「生长速率」，理由一条是"不依赖任何未定参数，一定出数"

而同一批 `t01`（问法更中性）它给的是**核相染色**，理由是"身份证据链第一环、一天出结果"。
**同一个问题两种问法，第一动作相反**，而两次都讲得通 —— 说明"第一件事做什么"这一格
**由模型的临场判断在掷硬币，不是由台账状态决定的**。

它自己在思考里承认了这一点：

> "台账 next_actions 里染色是第一条。我要有理由地推翻它 —— 但它算不算机械排序？"

三种答案都出现过：`b01` 说"染色不必先做"、`t01` 说"先染色"、`s01` 说"先测生长速率"。
学生如果是连问两次，会拿到互相矛盾的建议，而且系统不会告诉他这是两种权衡。

### 建议

`lab_report` 的 `say` 里应该给出**一个带条件的排序**，不是列表：
> 今天做 A（不依赖任何未定条件、X 天必出数）；A 之后并行做 B；
> 只有当你已经有融合子时，B 才升为第一位。

现在 `next_actions` 是一张平铺的表，谁都能当"第一条"，也谁都能被推翻。

## 十二、内容质量：这一轮最好的四条（判断基线，不能弄坏）

- **`u01` 把"要什么"改掉了**。学生问"怎么要设备"，它答"**明天不该要设备，该要机时和排期**；
  融合仪可以从桌上撤掉 —— 库里三篇食用菌融合全是 PEG 化学融合，没有一篇需要融合仪"，
  并给出三段"我明天就这么说"的原话 + 数字 + 出处。这是导师该做的事：**改问题**，不只是答问题。
- **`u04` 把一个可能一票否决课题的质疑拆对了**。保藏中心说"可能是同一个种"，
  它的回答是"老师的说法**对了一半**"：被记成同种异名的是**蝙蝠蛾被毛孢**（99.6% 同源），
  不是**蝙蝠蛾拟青霉**（18S 与 P. hepiali 100% 吻合、与中国被毛孢仅 72.4%）；
  并顺势把课题卖点从"近缘杂交"改成"跨属远缘融合"，指出审稿人盯的点会随之改变。
  回答"这不是同种异名，是跨属"这一条，**对了，也救了课题**。

# 第三轮：对照大厂做法（重点看了腾讯混元 Hyra 2.0）

## 十五、先说清楚 Hyra 2.0 是什么、不是什么

公开资料（腾讯混元官网 hy.tencent.com 与两家媒体的产品页）：

- **Hyra 2.0** 是腾讯混元 **2026-11-02** 发布的 AI 科研系统，1.0 在 7 月。定位从
  「让 agent 直接解题」转向「让 agent **造工具**、把经验沉淀成可复用资产」。
- 架构上有三件东西和我们这里直接相关：
  1. **三层组织**：Overall（对接人、管优先级与资源）／Mission（长期负责一个问题、对结论负责）／
     Worker（执行实验，**可以独立实验并质疑 Mission 的判断**）。
  2. **Review Worker**：需要独立验证时，起一个新 worker，**在新的上下文里先接触原始问题和证据**，
     再对执行者的结论做交叉验证；"复核发现的错误或更窄的结论范围都如实保留"。
  3. **三层记忆分离**：项目状态 / 每个 agent 的工作记忆 / 跨任务共享知识库 **Books** 分开存；
     Books 每条要写做法、理由、适用条件并**附原始证据**，按可信度分
     **「观察」「已验证」「约定」三级**，新证据出现时**可以修正已有记录**。
- **它是内部系统，不是对外 SaaS**。所以它的数字（量子码效率 +48%、香山芯片等效 2–3 个月迭代）
  对我们**没有对标意义** —— 那是在有评测器、有预算、有真实验证回路的场景里跑出来的。

拿它对照荣珂，值得看的是**它把哪几件事当成必须的结构**，而不是它的成绩。

## 十六、最扎人的一条：荣珂已经有这道门，只是把它断开了

腾讯把「独立复核」做成了必备的一层。而这台机器上的荣珂**本来就写好了同一件东西**：
`loop.py` 的 `mentor_trace_audit()` —— 判据表就写在函数注释里
（①必须查库 ②标的〔库·doc p.N〕必须真在本次命中里 ③联网补的必须标出来）。
**W36 之后它在 `run()` 结尾被主动不调用了**（`loop.py:4060-4074`）。

我做了个两边都能失败的对照实验（`_rk1_probe/review_worker_probe2.py`）：

| 输入 | citations | 判决 | 期望 |
|---|---|---|---|
| ① 3 处引注全部真实且在命中里 | 3 | **PASS** | 通过 ✓ |
| ② 真篇 + 编造一篇 `kbdeadbeef` | 2 | **FAIL**，`doc_not_in_hits` | 拦住 ✓ |
| ③ 真篇 + 编造页 `kb60993237 p.99` | 1 | **FAIL**，`page_not_hit` | 拦住 ✓ |

**这道门是好的，能分辨真假，区分度完整。** 结论不是"荣珂缺独立复核"，
而是**"荣珂花力气造的复核器，被拔了电"**。

> 顺带一个方法论教训：我第一版探针把引注写成〔kb…〕而内核正则要求〔库·kb…〕，
> 于是三条全部 `citations=0`、全部 `pass=False` —— **看起来"什么都能拦"，实际什么都没测**。
> 一个恒定失败的门会给假信心。这就是为什么每条判据都必须有"该通过的那一档"。

### 该做的（成本极低，收益最大）

把 `mentor_trace_audit()` 接回 `run()` 结尾，但**分级用**，不要一票否决：

- `must_query_library=False` 且 `citations=0` → 不判（打招呼、闲聊）；
- 有引注且全部 grounded → 通过；
- 有 `doc_not_in_hits` / `page_not_hit` → **不拦交付，但必须把这一条写进答复尾部**，
  并且明确区分两种成因（见第十七节）。

## 十七、Hyra 的「观察／已验证／约定」三级，正好能治我们第十节那个病

第十节测出来的事实是：模型 25 处引注里 **14 处所在的页它根本没看见**（在被切掉的 800 字之外），
**11 处所在的篇这一次检索都没命中**（靠上下文历史/方法卡引的）。
这两类在**当前形态下长得一模一样**，学生也分不出来。Hyra 的分级给了现成的解法：

| Hyra 的说法 | 在荣珂里对应的东西 | 现在有没有 |
|---|---|---|
| 观察（observation） | 「我记得库里有这一篇」但本次没命中 | 无，和"已验证"混在一起 |
| 已验证（verified） | 本次 `kb_read` 真的把那几页读出来了 | 有数据，但没标出来 |
| 约定（convention） | 课题组自己定的规矩（连作障碍、剂型、对照设置） | 无独立位置 |

具体到最小改动：**答复里每一个〔库·doc p.N〕后面再挂一个来源级**，
`〔库·doc p.N·读〕`（本次 kb_read 覆盖）/ `〔库·doc p.N·检〕`（本次检索命中、没读原文）/
`〔库·doc p.N·忆〕`（本次没检索到，来自历史）。三档在 UI 上给不同的视觉重量。
Books「新证据出现时可修正已有记录」对应的就是我们 `MEMORY`/台账已有的 `correction`，
现在它是自由文本，没接进引注链。

判据：对 u04 重跑，答复里 25 处引注应能分别落进「读／检／忆」三档，且三档都有非零。

## 十八、Hyra 的 Review Worker 还有一件我们要抄的：**它读的是原始证据**

原文："让 Review Worker 在**新上下文**里**先接触原始问题和证据**"，
目的写明是"排除执行者结论的影响"。

荣珂现在的 `deliver_attempt` / `gate` 都在**同一个上下文**里判，
判的是执行者自己写的 `summary` 和它自己标的引注。这正是我第一轮报告第七条那条
「几乎每轮都亮的警告」的根源 —— **自己检查自己，只能检查措辞**。

最小的落地方式不是加一个 agent（太贵），而是：**把复核输入换成原始回包**。
`mentor_trace_audit(calls, answer)` 的第二个判据本来用的就是 `calls[].result`（原始回包），
而不是 `summary`。把它接回去，等于**顺手把"独立复核"这件事也做了**，
因为它不读执行者的自述，只读台账和原文。

## 十九、Hyra 有、我们**不该**照抄的

- **递归自我改进 / 评估器共进化**：Hyra 的 Mission 靠"有无评测器"来闭环。
  荣珂的"评测器"是**实验本身**，一个周期三周起步，不可能内层循环跑几百次。
  照抄会得到一台自信地自我确认的机器。我们要的是**慢验证、可回滚、可被老师说"不对"**。
- **异步多 worker 并行**：学生一次只有一个课题、一块实验台。并行只会在**记忆**上出问题
  （第一轮已测到 `memory_recall` 把上一题的成功配方带进新题）。
- **它的成绩数字**：不在一个赛道，不构成基线。

## 二十、所以真正的排序（合并三轮）

1. **先接回复核器**（第十六节）—— 代码已经在，成本最低，能立刻把"编造"变成"看得见"。
2. **修 800 字预览**（第十节）—— 让 8/10 的命中回到模型视野，这条修完上面那条的"忆"档会大幅减少。
3. **加来源级三档**（第十七节）—— 把"读／检／忆"分开，学生才知道哪句能直接写进论文。
4. **写稿答复回填**（第二节）—— 学生看得见东西。
5. **寒暄不调工具**（第三节）—— 第一次用不会以为坏了。

前三件的共同点：**都不需要新模型、不需要新框架，全在已有的 `loop.py` / `gate.py` 里**。
这正是 Hyra "解出一道题只得到一个答案，升级一件工具让所有下游任务受益"那句话对我们唯一的用处。
