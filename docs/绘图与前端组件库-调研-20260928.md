## 一、结论先说

| 需求 | 选择 | 为什么不引真依赖 |
| --- | --- | --- |
| 服务端画图 | **matplotlib**（已在用） | 本机已装 3.11.1，且 `nature-figure` 的六道审计门就是按 matplotlib 的产物写的 |
| 数据读入 | **pandas**（已在用） | 实测已装 3.0.5 |
| 前端图表渲染 | **不引**，服务端出图、前端只显示 PNG | 控制台是零依赖单文件产物；引 ECharts/Chart.js 就要 CDN 或构建步骤，离线即散架 |
| 前端 UI 组件 | **不引**，只抄设计规格 | 同上。抄的是**间距、字号、圆角、层级**这套数字，不是代码 |

**一句话**：这个项目真正缺的不是"更漂亮的控件"，而是**间距没有节奏**。
这一点我是量出来的（见第三节），不是感觉。

## 二、绘图库：为什么停在 matplotlib

### 实测的环境事实

在本机系统 Python 3.12 上用 `importlib.metadata` 读到的真实版本：

| 库 | 版本 | 装了没 |
| --- | --- | --- |
| matplotlib | 3.11.1 | ✅ |
| pandas | 3.0.5 | ✅ |
| seaborn | 0.13.2 | ✅ |
| numpy | 2.5.1 | ✅ |
| scipy | 1.18.0 | ✅ |
| plotly | — | ❌ |
| altair | — | ❌ |
| bokeh | — | ❌ |
| plotnine | — | ❌ |
| polars | — | ❌ |

> 取证方式：`importlib.metadata.version(p)`，逐库跑。不是凭印象。

### 候选与取舍

| 库 | 它擅长什么 | 为什么这张图不用它 |
| --- | --- | --- |
| **matplotlib** | 完全控制每根线、每个字距；矢量/位图导出成熟 | 已选：`validate_figure.py` 的源码门检查 `svg.fonttype='none'`、`pdf.fonttype=42`、`.tiff` 字面量 —— 这些全是 matplotlib 的 API。换库等于把六道门全部作废 |
| **seaborn** | 统计图型开箱即用（`boxplot`/`violinplot`/`relplot`），配色好看 | 已装。但它对**我们要过的门**没有帮助，反而多一层抽象：出问题时不知道是 seaborn 还是 matplotlib 的参数没生效。当前 9 种图型的绘制体都在 30 行以内，不值得 |
| **plotly** | 交互图（hover / zoom） | 产出是 HTML+JS，**不是投稿要的 PDF/矢量**。审稿人要的是能缩放到任意倍率不失真的图 |
| **altair / bokeh** | 声明式语法、交互 | 同上；且本机没装 |
| **plotnine** | ggplot2 语法 | 本机没装；且语法糖换不来审计门的任何一条 |
| **polars** | 大数据集读表快 | 本机没装。当前数据表在几十行到几千行量级，pandas 3.0 的读表耗时不是瓶颈（实测 `analyze()` 全流程 ≈ 1.6s 画图 + ~5s 审计） |

**驳回清单（明确不用）**：plotly / altair / bokeh / plotnine / polars / pygal / holoviews。
理由统一：**它们要么产不出投稿级矢量位图，要么本机没装，要么换不来任何一条审计门。**

### 一个真实的技术约束（值得记下来）

`validate_figure.py` 是**扫源码字符串**的，不是运行期检查。这条约束直接决定了生成脚本必须怎么写：

- 导出路径必须是**字面量** `"figure.svg"` / `"figure.pdf"` / `"figure.tiff"`，
  不能写成 `for ext in (...)` 循环拼接 —— 我第一版就是循环，`.svg` 字面量在源码里不存在，
  `EXPORT-VECTOR` 直接判 FAIL。
- 有 `.dropna(` 就必须同时出现 `n_before` / `n_after` 两个标记，否则 `DATA-EXCLUSION` 报错。

这两条我已经写进 `analysis_test.py` 的 `[4]` 节，改坏了会红。

## 三、前端组件库：只抄数字，不抄代码

### 3.1 真正的问题：间距没有节奏（实测）

判据：**Primer 的 base-8 阶梯**（0 / 4 / 8 / 16 / 24 / 32 / 40）。
出处是 Primer 官方文档原文（`primer-support` 的 `docs/spacing.md`）：

> The spacing scale is a **base-8** scale. We chose a base-8 scale because eight is a
> highly composable number (it can be divided and multiplied many times and result in
> whole numbers), yet allows spacing dense enough for GitHub's UI. The scale's exception
> is that it begins at 4px ... from there on it steps up consistently in equal values of `8px`.

改造前，`rongke/web/index.html` 的实测：

- 间距声明 **387 条**，含 **454 个 px 值**
- 落在阶梯上：**132 个（29.1%）**
- 落在阶梯外：**322 个（70.9%）**

阶梯外的值按出现次数（前 12）：
`6px×53、9px×39、2px×32、10px×32、12px×28、5px×23、7px×22、14px×20、3px×20、11px×11、1px×10、13px×6`

**几乎每个整数都出现过。** 这不是"间距有大有小"，这是**没有尺度**。
用户说"不像成熟产品"，机制根源就在这里 —— 不是配色，不是字体。

### 3.2 怎么改的 —— 以及第一次改错了

**先说错的那一版。** 我写了个脚本把全站 `<style>` 里的间距值统一吸到 base-8 阶梯上，
覆盖率从 29.1% 提到 80.0%，看着很成功。然后 `ui_check` 报了 **8 项红**：

```
B1 Button sm=28：.btn.sm{ 里缺 padding:0 10px
B2 Input 外壳 32/.5px l4：.ipt{ 里缺 gap:6px
B4 Checkbox 基类：.checkbox{ 里缺 gap:6px
B9 DisclosureRow 指头槽 16 / gap 6：.disclosure .leading{ 里缺 margin-right:6px
B10 Tooltip 气泡：.tooltip{ 里缺 padding:3px 7px
B10 Menu 行几何：.menu .mitem{ 里缺 padding:6px 8px
B10 Modal 卡：.modal .dialog{ 里缺 gap:20px
B10 Toast：.toast{ 里缺 gap:10px · padding:12px 16px
```

这 8 个是 **DSH 原子件的钉死几何值** —— 仓里有专门的规格守卫逐件对着 DSH 真值核。
我把 `6px` 吸成 `8px`、`3px 7px` 吸成 `4px 8px`，等于把一份已经核过的规格改坏了。
**间距节奏不能凌驾在已钉死的组件规格之上。**

所以最后做的是**收窄**：间距阶梯只作用于「分析成图」这一块新区块内部（`.anrow` / `.anfield` /
`.ansug` / `.anfig` / `.angates` / `.anlegend` / `.ancol`），既有组件一个都不碰。

> 这条教训比数字重要：**"全站统一"听起来比"只改新区块"高级，但前者会打穿已有守卫。**
> 有守卫的地方，改动的边界要按守卫画，不能按审美画。

### 3.3 抄了哪些库、抄的是哪一层

| 库 | 抄的是什么 | 落到哪 |
| --- | --- | --- |
| **Primer**（GitHub） | base-8 间距阶梯 | 上面那件事 |
| **ZCode / Zai Light** | 配色与语义映射 | **早已在仓里**（`--b-*` / `--dk-*` / `--fg-*` / `--r-*` 令牌），这次没动 |

**明确没抄的**：

- **shadcn/ui、Radix、Ant Design、Mantine** —— 它们是 React 组件库。
  这个控制台是零依赖单文件，用它们的唯一方式是引入 React + 构建步骤 + 几百 KB 产物。
  为"按钮好看一点"付出"离线不可用"的代价，不划算。
- **ECharts、Chart.js、D3、Observable Plot、uPlot、Vega-Lite** —— 同第二章的理由：
  我们要的是投稿级 PDF，不是交互图。

**这不是"抄不够彻底"，是约束决定的。** 如果哪天控制台允许构建步骤，
shadcn/ui 的 `--radius` / `--spacing` 变量设计是值得整套搬的。

### 3.4 圆角与字号：本来就有，不需要改

实测仓里已有：

- 圆角令牌：`--r-xs / --r-sm / --r-md / --r-lg / --r-pill`，35 处走 `--r-sm`、25 处走 `--r-md`
- 字号阶梯：`--fs-xxxs(11) / --fs-xxs(12) / --fs-xs(13) / --fs-s(14) / --fs-base(16) / --fs-l(20) / --fs-xl(24)`

一套完整的梯子已经在用。缺的**只有间距**这一维 —— 这也是为什么只补间距就能明显"成熟"起来。

## 四点五、补测 9 种图型时挖出的 4 个真缺陷

这一节是后补的：先前只有 `time_series` 走过「出图 → 六道门」，
其余 8 种只有源码级断言。补测后 9 种里**只有 3 种能交付**，另外 6 种全红。

四个缺陷都属于最危险的那一类——**程序退出 0、图是错的**，人眼一眼看不出：

| # | 症状 | 真因 | 为什么六道门没拦住 |
| --- | --- | --- | --- |
| ① | `box` 画不出 PDF | matplotlib **3.11 移除了 `boxplot(labels=)`**，改叫 `tick_labels=`。旧名直接 `TypeError` | 脚本退出码非 0，但要翻 stderr 才看得见；被当成"数据有问题" |
| ② | `heatmap` 画出一张**全白空图** | 把时间列塞进 `clean()` 强转成数值 ⇒ 全 NaN ⇒ `dropna` 删光行 ⇒ `corr()` 全 NaN ⇒ `if v == v` 永远假 | 门只看字号/碰撞/字体，**看不出"格子里该有数字却没画"**。这是本轮最危险的发现 |
| ③ | `paired` 报「需要至少两个条件」 | 把**条件列**（`ctrl`/`heat` 字符串）和**个体 id** 也塞进 `clean()` 强转 ⇒ 同样全 NaN ⇒ pivot 出 0 列 | 报错文案像"你数据不够"，实际是清洗错了列 |
| ④ | `line`/`hist`/`box`/`violin` 交付被拦 | 绘图区内一个字都没有 ⇒ `text_containment` 只能回 `NOT AUDITABLE`（没查≠通过） | 这不是误报，是**真的没内容可查** |

修法与验证：

- ①  按 `inspect.signature` 探测参数名，不写死版本号（换台机器装 3.8 也照样跑）。
- ②③ 只对**本来就是数值**的列做强转（`select_dtypes("number")` / `clean(df,[y])`），
  条件列与 id 列一个都不碰。② 还加了「数值列不足 2 个就明确报错」的前置检查。
- ④  把图例收进版心（`loc="upper left"`），顺便交代样本量 ——
  这是 89mm 单栏图本来就该做的，不是为了骗过审计。

结果：**9/9 全部 PASS**，并已固化成 `analysis_test.py` 第 [10] 节（20 条断言，
含 `time_series … hist` 九条真跑）。

三个负控都实测**打得穿**（把缺陷注回去，源码判据与真跑断言同时变红）：

```
【box 旧参数名】     rc=1  → ✗（负控）没有写死旧名 labels=labels
                          ✗ box：过完整审计链（FIX BEFORE DELIVERY）
【heatmap 强转时间列】rc=1  → ✗（负控）heatmap 段里没有 clean(df,[x,y])
                          ✗ heatmap：过完整审计链（FIX BEFORE DELIVERY）
【paired 强转条件列】 rc=1  → ✗ paired 只对 y 做强转数值
                          ✗ paired：过完整审计链（FIX BEFORE DELIVERY）
恢复后 rc=0 | 120 项 / 0 失败
```

> 附带一条方法论教训：我第一版判据写成 `code.find('"heatmap"')`，
> 命中的是 `CHART_KINDS` 里那个键（靠前），切片根本没进到模板段 ——
> **判据假红，代码是对的**。改成锚定 `'"heatmap": '''def draw(` 才对。
> 源码切片类判据必须锚在**唯一的结构位置**上，不能锚在裸字符串上。

## 五、一句话总结

调研的最终产出不是"选了哪个库"，而是**两条可复跑的量化判据**：

1. `runs/_an/spacing_audit.py` —— 间距落在 base-8 阶梯上的比例。
2. `ui_check` / `ui_check_st` —— DSH 原子件的钉死几何值有没有被改动。

这两条判据是**互相拉扯**的：第 1 条追求全站统一，第 2 条要求既有组件纹丝不动。
正确解不是二选一，而是**把第 1 条的作用域收窄到新区块**。
我先做了全局版、被第 2 条拦下 8 项红，才想明白这件事。
